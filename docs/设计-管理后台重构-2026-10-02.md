## 1. 现状

已有 13 个入口：概览、用户、订单与成交、充值、提现、托管方、资产与交易对、合约、HOUSE、风控开关、账本、审计、报表；统一的 ConsoleShell、全局搜索（⌘K）、游标分页 DataTable、FilterBar、Drawer 详情、DangerAction 确认。角色 ADMIN / OPERATOR / FINANCE / AUDITOR 与权限点已存在。

用户感受"单调、能管的很少"的原因：

| 问题 | 事实 |
|---|---|
| 没有动效、视觉平 | 后台没有用 `motion`，无页面过渡、无数字滚动、无图表动画；登录页是一张素卡 |
| 给用户加减币"无法处理" | 资金调整走双人审批（`/admin/v1/approvals`，本人不能批自己的，`ADMIN_SELF_APPROVAL`），而现在只有一个管理员，任何调整都永远停在待审批；入口藏在"账本 → 调整"tab，用户详情里没有 |
| 提现"需要审核" | 审核队列已有（`/withdrawals/{id}/review`），但从用户详情、概览都没有直达，没有批量与备注 |
| 充值 | 只有列表，没有人工入账、错误网络处置、补记 |
| 管理员 | 只能用 CLI `exchangectl admin create`，后台没有管理员与角色页 |
| 其它缺口 | 资产/交易对/合约只能改状态不能新增编辑；没有公告与站内通知；没有仓位管理与强制平仓；风控只有开关没有告警；报表是纯表格；没有系统设置页 |

## 2. 决定

| # | 决定 | 说明 |
|---|---|---|
| 1 | 双人审批改为**可配置**：功能开关 `admin.two_person_approval`，测试服关闭。关闭时，有权限的单个管理员填写理由即可直接执行资金调整、保险基金注资、大额提现批准；打开时走现有审批流 | 现在只有一个管理员；审批引擎保留，有第二个管理员后再开 |
| 2 | 单人模式仍有护栏：单笔资金调整上限与每日累计上限（配置，默认 100,000 USDT 等值 / 500,000），超过即使开关关闭也要双人；全部写审计 | 防误操作 |
| 3 | 后台视觉**独立设计**（用户已允许）：浅色为主，可切深色；明确的品牌感与动效；仍复用 `packages/ui` 的基础组件与 DataTable/Form 能力 | §6 |
| 4 | 管理员账号在后台管理（创建、角色、停用、重置口令与身份验证器、会话），CLI 保留为兜底 | |
| 5 | 后台访问限制与登录 TOTP 维持用户此前决定（暂不限制、`admin.login_without_totp` 测试服开） | |
| 6 | **2026-10-02 补充（C3b 审查）**：护栏范围扩到交易参数——交易对/合约的状态、费率、风险阶梯、杠杆、`reference_symbol` 的改动只允许 ADMIN，服务端二次确认并延迟生效；清空 HOUSE 正在报价或作为永续指数的交易对的参考符号直接拒绝；阶梯/MMR 改动的预览必须列出按新参数会被强平的仓位数与名义；`admin.two_person_approval` 打开时这些改动也走双人 | 一次调用就能改费率到 10% 或让高杠杆仓位秒级强平，不能只靠前端确认词 |
| 6 | ASTRA 模拟市场的后台页面（ASTRA 设计稿 §6）由本会话实现，等编码会话把 `market-sim` 后端接口做出来后接入 | §8 |

## 3. 信息架构（重排）

```text
概览        指标卡、趋势图、待办（待审提现、待处理充值、待审批、告警）、系统健康
用户        列表 → 详情（资料、身份与安全、余额与资金操作、订单、成交、仓位、充提、登录与设备、风控、备注与标签）
资金        充值 · 提现审核 · 内部划转 · 托管方 · 资金调整 · 审批 · 对账与系统科目
交易        订单 · 成交 · 仓位 · 强平记录 · 合约与保险基金 · HOUSE 敞口
市场        资产与网络 · 交易对 · 合约规格 · 费率 · 参考符号映射 · 上架向导 · 模拟市场（ASTRA，后续）
风控        功能开关 · 风控规则 · 告警 · 限额配置
运营        公告 · 站内通知 · 帮助内容 · 首页推荐位（可选）
系统        管理员与角色 · 审计日志 · 报表 · 系统健康 · 设置
```

侧栏按上述分组折叠；顶栏：环境标识、全局搜索（用户/订单/交易哈希/地址）、待办角标、管理员菜单（主题切换、退出）。

## 4. 关键工作流

### 4.1 用户详情（Drawer 改为全页 + 侧边摘要）

- 头部：头像/首字母、邮箱与手机（脱敏，可点开）、UID、状态 Badge、标签、注册时间、最近登录、风险评分。
- Tab：
  - 资料与身份：身份列表、绑定/解绑（需理由）、条款版本、语言时区。
  - 安全：TOTP 状态与重置、密码重置（发邮件链接或临时口令，审计）、设备与会话（撤销）、登录历史。
  - 余额与资金操作：现货/合约账户各资产可用/冻结/估值；**调整余额**按钮 → 表单（账户类型、资产、方向增加/减少、数量、理由、可选关联单号）→ 单人模式直接执行并显示分录；双人模式创建审批；**冻结/解冻**指定资产数量（新账本分录类型 `ADMIN_FREEZE`/`ADMIN_UNFREEZE`，用于风控）。
  - 订单、成交、仓位：筛选与导出；强制撤单；**强制平仓**（市价，走 derivatives-service 新接口，需确认与理由）。
  - 充值与提现：该用户记录，直达审核。
  - 风控：规则命中、告警、手动置 `RISK_REVIEW`/恢复。
  - 备注与标签：管理员备注（时间线）、标签（VIP、可疑、测试）。

### 4.2 提现审核

- 队列视图（默认待审核，最旧在前）、筛选（资产、网络、金额区间、风险分、用户）、列表行展开摘要。
- 详情：金额与手续费、地址与地址簿状态（新地址/冷却中）、用户当日/当月限额占用、风险评分明细、用户近期提现、托管方状态与回调时间线。
- 操作：批准 / 拒绝（理由）/ 搁置并备注；批量批准低风险（勾选 + 一次确认，逐条审计）；大额按 §2 第 2 条走双人。
- 概览与侧栏显示待审数角标，SSE 或 15 s 轮询更新。

### 4.3 充值处理

- 列表（状态、网络、确认进度、浏览器链接、托管方交易号）；筛选与导出。
- 待处理项（错误网络、未支持代币、低于最小额、账户关闭或不符合资格）：
  - 人工入账：只对已记入 `UNCLAIMED_DEPOSIT` 的充值，把原币种、原数量放给用户（账本新操作 `ReleaseUnclaimed`，分录仍为 `DEPOSIT_CREDIT`），不允许改资产或数量；未支持代币（账本没有记账）只能拒绝或标记已处理，要补偿走调账。
  - 拒绝：只把待处理项标记为已处理（留言与审计），资金留在 `UNCLAIMED_DEPOSIT`。
- 补记充值（托管方已到账但回调丢失）。**2026-10-02 决定**：优盾网关（官方 SDK 只有 CreateAddress、Withdraw、CheckAddress、SupportCoins、ExistAddress）没有按交易号查询的接口，无法向托管方核对，改为"管理员先在优盾商户后台或区块浏览器核对，再录入；系统做内部核对；按资金操作的护栏审批"：
  - 录入 `tradeId`、网络、地址、数量、`txHash`、理由。系统核对：网络由托管方服务；地址属于该网络上的某个用户；`UDUN:<tradeId>` 没出现过，且（网络、`txHash`、地址）也没出现过；数量符合资产精度。入账走与回调相同的路径（CONFIRMED → `DEPOSIT_CREDIT`），低于最小额同样进 `UNCLAIMED_DEPOSIT`；记录来源 `MANUAL` 与录入人。
  - 护栏与调账相同（§2）：单人模式按 USDT 估值受同一套单笔与 24 小时限额，超出或双人模式时第二人批准，共用审批记录；确认框明示"托管方未核对"。
  - 之后真回调到来：按 `tradeId` 匹配到 `MANUAL` 记录即标记"已应用"、不再入账；回调的数量、地址或资产与录入不一致时不自动更正、不二次入账，置为 `DISCREPANCY` 待处理项并告警。
  - 充值列表可筛"补记且尚无回调"的记录；`exchangectl wallet reconcile --network UDUN` 的报告单列这些记录——托管方余额里没有对应到账，就是录错。
  - 以后可选：EVM 网络用 Alchemy 按 `txHash` 核对转账日志；TRON、BTC 暂无客户端，不做。

### 4.4 资产与交易对上架

- 资产：新增/编辑（代码、显示名、精度、图标、分类、充提开关、风险开关）；网络子表（provider、币种编码、确认数、最小额、手续费、开关）。
- 交易对：新增/编辑（tick、lot、最小名义、价格保护带、费率档位、参考符号与倍数）；状态机按钮。
- 合约：规格与风险阶梯编辑（阶梯表格可增删行，校验单调性）。
- 上架向导：从 CSV 粘贴 → 预览 diff → 应用（调用现有 `instruments apply` 等价接口）。

### 4.5 运营

- 公告：列表、新建/编辑（标题、正文 Markdown、分类、置顶、定时发布、生效语言）、预览、发布/下线；用户站与手机站从 `GET /v1/announcements` 读取（替代仓库内 Markdown）。
- 站内通知：向单个用户/标签/全体发送（标题、正文、跳转），可选同时发邮件；发送记录与送达数。
- 帮助内容：同公告的编辑器，分目录。

### 4.6 系统

- 管理员与角色：列表、创建（邮箱、角色、初始口令一次性显示）、停用/启用、重置口令、重置 TOTP、查看会话；角色权限矩阵只读展示。
- 审计：全量筛选（操作人、对象、类型、时间）、详情 diff、导出 CSV。
- 报表：交易、钱包、合约、用户增长、HOUSE 盈亏，图表 + 表格，时间范围选择。
- 系统健康：各服务就绪与版本、Kafka 滞后、DLQ 条数、对账状态、托管方状态、行情源状态。
- 设置：双人审批开关与限额、提现审批阈值、默认分页、主题。

## 6. 视觉与动效

方向：浅色为主的"控制台"，深色可切；专业但有品牌感——侧栏深色（`#0F1420`）配品牌黄高亮，内容区浅灰白，卡片白底细边与柔和阴影，数字用等宽数字字体，图表用品牌色系；深色模式复用用户站的令牌。

| 场景 | 动效 |
|---|---|
| 登录页 | 左半屏品牌区：渐变网格 + 缓慢漂移的两团光斑 + 字标描边绘制（1.2 s）；右半屏表单卡片淡入上移；输入框聚焦时底线从中间展开；登录中按钮变进度条，成功后勾选打勾再过渡进入；验证码为 6 格分段输入，粘贴自动填充 |
| 进入控制台 | 侧栏从左滑入 240 ms，内容区交错淡入（卡片每 40 ms）；之后的页面切换只做内容区淡入上移 160 ms |
| 概览 | 指标卡数字 CountUp；折线/柱状图描画 600 ms；待办卡有新项时角标弹跳；系统健康点呼吸动画（仅异常时） |
| 表格 | 首屏行错峰淡入（≤ 12 行）；行悬停浮起 1 px 阴影；新数据到达显示顶部提示条滑入，点击刷新；排序切换箭头旋转 |
| 详情 | Drawer/全页从右滑入 240 ms，背景遮罩淡入；tab 切换下划线滑动 |
| 操作 | 确认对话框缩放淡入；提交中进度条；成功 toast 从右上滑入并带勾选动画；危险操作按钮按下缩放 |
| 侧栏 | 折叠/展开宽度过渡 200 ms，图标保持，文字淡出；分组展开手风琴 |
| 空态/加载 | 骨架屏闪光；空态插画轻微上下浮动 |

约束同用户站：只动 transform/opacity，`prefers-reduced-motion` 时全部关闭；登录页 Lighthouse ≥ 90，控制台页 ≥ 85；首屏 JS gzip ≤ 250 KB（图表库按需）。

## 7. 协作与分工

| 事项 | 新会话（后台） | 编码会话 |
|---|---|---|
| 代码范围 | `web/apps/admin`、`internal/admin`、`cmd/admin-service`、`api/admin`；为后台在其它服务新增接口（提交信息注明 `admin:`） | 其余全部：用户站、行情、撮合、钱包、ASTRA 后端 |
| 共享包 | `packages/ui` 只新增文件；要改既有组件先在消息里说明，由文档会话协调 | 同左 |
