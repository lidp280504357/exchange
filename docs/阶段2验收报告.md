## 4. 故障场景覆盖

| 场景 | 方式 | 结果 |
|---|---|---|
| 撮合主进程崩溃 | `matching-failover.sh`：第二个实例在引擎租约上等待，主进程被 `kill -9` | 备机取得 PostgreSQL 咨询锁，由快照与 WAL 重建订单簿，从已提交位点继续；崩溃前的挂单恰好成交一次、账本结清；Docker 把崩溃实例拉起为新备机，优雅停掉第二个实例后第一个再次接管 |
| 链节点不可用 | `chain-outage.sh`：主机防火墙丢弃 wallet-service 出网流量 | RPC 20 秒超时，扫描停在原处，服务仍就绪，分配地址与充提查询正常；恢复后追上链高 |
| 参考行情中断 | `reference-outage.sh`：丢弃 market-data-service 出网流量 | 参考价 5 秒过期，做市撤掉报价，平台自己的行情照常；流 30 秒无数据后断开重连（本阶段修复，之前要等 TCP keepalive）；恢复后回填、做市重新报价 |
| 链重组 | 扫描器集成测试 | 父哈希不符时回退"确认数 + 6"块重扫，被丢弃的充值记为 ORPHANED，重新出现时回到 DETECTED，入账只一次 |
| 签名被拒、热钱包不足、费用超上限 | 钱包集成测试 | 签名被拒记 FAILED 待人工；热钱包不足或费用超上限时停在 APPROVED 并挡住后续提现以保持 nonce 连续；10 分钟未上链按同 nonce 提价 25% 替换 |
| 账本不可达 | 交易服务测试 | 冻结结果未知的订单由恢复任务幂等补完；终态订单的解冻在账本恢复后重试 |
| 阶段 1 的场景 | Redpanda、ClickHouse、Redis 停机，PostgreSQL 重启 | 见[阶段 1 报告](阶段1验收报告.md) §4，本阶段未改变其行为 |

## 5. 对账结果（测试环境，2026-09-29）

- 账本对账 7 项（`JOURNAL_BALANCED`、`ACCOUNT_MATCHES_LINES`、`SNAPSHOT_MATCHES_ACCOUNT`、`TRADES_SETTLED`、`TRADES_NUMBERED`、`TRADE_SETTLE_MATCHES_TRADES`、`TRADE_FEE_MATCHES_TRADES`）在压测与故障注入之后全部 0 差异，没有 FAILED 的结算。
- 链上对账（不变量 4）：热钱包与充值地址的链上持有等于 −(`DEPOSIT_PENDING` + `WITHDRAWAL_PENDING`) − 未记账 gas，缺口 0。
- ClickHouse：各服务 outbox 与 `events` 按主题核对为 0（`admin` schema 已加入）；读模型与事件一一对应（成交 12,074 笔、订单变化 73,933 条），充提读模型各状态笔数与 wallet-service 的表一致，一分钟 K 线笔数之和等于成交数（`ops.sh` 断言）。

## 6. 资源与环境

- 压测发现并修复：nginx 用镜像默认的每 worker 1024 连接（公网入口约 1,000 条 WebSocket 上限）→ 仓库加 `nginx.conf`（16384 连接、65536 描述符）；网关 192 MiB 内存约 3,000 条连接 → 512 MiB。
- t2.medium 是突发型实例：全链路约 100 单/秒时 CPU 已 91% 忙。2026-09-29 晚在大量压测、部署与测试之后测试服一度无响应（网站 522、SSH 握手超时），推测 CPU 积分耗尽，需要在 AWS 控制台确认（改为 Unlimited 或重启）。用户决定不升级实例，后续避免在测试服上做持续高负载。

## 8. 风险登记更新与下一阶段依赖

风险：

- **测试服容量与突发积分**：一台 2 vCPU 突发型实例承载全部组件；持续高负载会耗尽 CPU 积分使整机不可用。阶段 3 增加合约服务后，常驻负载会再上升。
- **撮合与结算的单机上限**：交易服务逐条消费订单事件，是压测中最先饱和的下游之一（压测报告列了优化方向）。
- **外部依赖**：Alchemy（免费额度，`eth_getLogs` 10 块窗口）、币安公开接口、Cloudflare。

阶段 3（§7 USDT 永续合约）依赖：

1. 合约账户与现货账本逻辑隔离（ADR-0001 的科目扩展）与标记价、指数价、资金费率、强平公式（需求 §11.7）。
2. 撮合引擎复用：合约交易对按分片进入同一引擎，保证金检查在交易服务侧（ADR-0002）。
3. 行情：多源指数价在只有一个参考源（币安）时的降级规则（需求 §11.7"可用价源 < 2"）。
4. 模拟资金：合约只在测试环境、模拟资金下运行（§6.2 第 5 条）。
