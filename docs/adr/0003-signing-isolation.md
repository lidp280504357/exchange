# ADR-0003：签名服务与业务服务隔离，私钥不进入业务进程

- 状态：已接受（2026-09-29）
- 关联：需求 §5.10、§11.6；决策 #23

## 背景

热钱包私钥是交易所最高价值资产。任何能执行代码的业务漏洞（SQL 注入、依赖投毒、SSRF）一旦能触达私钥，损失不可逆。

## 决策

1. `signer-service` 独立进程与独立网络策略，只暴露一个接口：对"带审批单 ID、金额、目的地址、nonce"的请求签名。
2. 签名前独立校验：审批单存在且已通过、金额与地址与审批单一致、地址在白名单、单笔/日累计未超限；任一不符拒签并审计。
3. 测试网阶段私钥存加密 keystore（age 或 KMS 加密），启动时解密到内存；生产升级 HSM/MPC，接口不变。
4. 用户充值地址由 xpub 派生，业务服务只持有 xpub；归集与提现广播由钱包服务发起、签名服务签名。
5. 所有签名请求与结果写审计事件；私钥、助记词、keystore 口令不得出现在日志、环境变量文件以外的任何地方。

## 理由

把"能花钱"的能力收敛到一个最小、可审计的进程；即使业务服务被完全攻破，攻击者拿到的也只是"申请签名"的能力，而申请受审批单与限额约束。

## 后果

- 提现多一次内部 RPC 与审批单校验，延迟增加可接受。
- 需要单独的密钥轮换与备份流程（阶段 2 交付）。

## 备选

私钥放钱包服务配置（被否决：无隔离）；直接用 KMS 签名（可作生产备选，本地开发不便）。
