# ADR-0005：高风险能力由功能开关控制，默认关闭

- 状态：已接受（2026-09-29）
- 关联：需求 §5.14、§14；实施计划执行原则 7

## 背景

合约、提现、真实链上广播、新资产、新交易对、外部行情源都可能造成不可逆损失或合规问题。上线节奏需要按地区、账户、资产、交易对逐步放开，而不是一次全开。

## 决策

1. 所有高风险能力在代码中以开关名引用，开关存 PostgreSQL 表 `flags`，维度：全局、地区、账户状态、资产、交易对、用户白名单。
2. 服务本地缓存 5 秒并订阅变更事件；缺失配置一律视为关闭。
3. 开关变更走管理后台 RBAC，写审计事件；全站、单交易对、单资产三级紧急开关可一键关闭。
4. 学习前提下地区允许列表默认全开，但机制保留，方便以后按地区收紧。

## 理由

放量与回退都变成配置操作，而非发版；审计能回答"某功能何时对谁开放过"。

## 后果

- 每个受控路径多一次开关检查（本地缓存，代价可忽略）。
- 测试必须覆盖"开关关闭"分支，避免默认关闭导致的功能误判。

## 备选

编译期常量或环境变量（被否决：无法分维度、无审计、改动需重启）。
