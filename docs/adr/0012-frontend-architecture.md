# ADR-0012：前端采用三应用两包、共享设计系统与单一 WebSocket 数据层

- 状态：已接受（2026-09-30）
- 关联：设计文档 `docs/设计-体验重构与市场钱包扩展-2026-09-30.md` §4、§5、§12；替代阶段 1–3 的"PC 与手机共用一个响应式 H5"做法

## 背景

阶段 1–3 的前端是一个响应式 H5（`web/h5`）加一个浅色管理后台（`web/admin`）。2026-09-30 的逐文件诊断（设计文档附录 A）找到两类根因：

- 卡：订单簿每条消息全量重建，私有推送触发整串 REST 重拉，切页断开并重连 WebSocket，没有代码分割。
- 不连贯：没有设计令牌，tab、下拉、校验各有多种写法，同一套逻辑在多个页面复制并已经漂移。

用户同时决定：PC 与手机做成两套站点，按二级域名区分，后台独立域名，内容与动效要多。

## 决策

1. **目录**：`web/` 是一个 pnpm workspace，包括：
   - 共享包 `web/packages/core`：数据层；
   - 共享包 `web/packages/ui`：设计系统；
   - 三个应用 `web/apps/pc`（`astras.vip`）、`web/apps/m`（`m.astras.vip`）与 `web/apps/admin`（`admin.astras.vip`）。

   旧的 `web/h5`、`web/admin` 在新页面完成前保留为过渡版本：旧 H5 挂在 `/h5/`，旧后台留在 `astras.vip/admin/`。新站点对应页面完成后删除。
2. **共享边界**：取数、推送、格式化、校验、i18n、枚举映射、路由常量、组件全部放在共享包；页面、布局、导航属于各应用。应用之间不互相 import。OpenAPI 类型只在 `packages/core` 生成一次。
3. **单一 WebSocket 数据层**：
   - 一个应用一条连接，公共频道与私有频道复用这条连接。
   - 订阅按引用计数，归零后延迟 15 秒再退订，所以切页不重连。
   - 重连采用指数退避加抖动，并自动重放订阅。
   - 深度与私有频道校验序号，断号时只发一次重订阅。
   - 页面隐藏时暂停高频频道。
   - 高频行情存在 React 之外，按帧合并通知（`useSyncExternalStore` + `requestAnimationFrame`）。
   - 私有推送直接写入 TanStack Query 缓存，不触发整串重拉。
4. **设计系统**：
   - 令牌用 CSS 变量定义，Tailwind 4 用 `@theme` 引用。组件只用语义类名，禁止十六进制颜色。
   - 用户站默认深色，后台为浅色并可独立设计视觉。
   - 涨跌色可以对调（`data-updown`）。
   - 组件基于 Radix（无样式、可访问）自己实现样式，全部带 Storybook 页。
5. **动效规则**：
   - 只动 `transform` 与 `opacity`。
   - 价格闪动用 CSS class，不用 JS 计时器。
   - 列表进入动画只对首屏行生效。
   - `prefers-reduced-motion` 时全部关闭。
   - 性能预算不达标时先删动效。
6. **设备分流**：nginx 按 User-Agent 在 HTML 导航时把手机访问 PC 站、桌面访问手机站的请求 302 到另一个站，路径保持不变。页脚"切换到电脑版 / 手机版"写 `site_pref` Cookie（`Domain=.astras.vip`），有这个 Cookie 就不再分流。两站路由路径完全一致，分享链接可以互通。
7. **性能预算**（设计文档 §12.1）是验收门槛：
   - 路由级懒加载，图表库不进首屏；
   - 生产构建不公开 sourcemap；
   - `web-vitals` 采集；
   - Lighthouse CI 对两站各三页出分。
8. **后台访问限制**：`admin.astras.vip` 由 nginx IP 白名单（服务器上的 `snippets/admin-access.local.conf`）或 Cloudflare Access 限制，二选一，另加管理员 TOTP 登录。

## 理由

- 两套站点的页面骨架不同（顶栏 vs 底部 tab、表格 vs 卡片），硬做响应式会让两端都妥协；数据与组件共享之后，第二个站点的增量主要是布局。
- 卡顿的根因都在数据层；把它集中到一个包里，修一次三个应用都受益。
- 令牌与组件库消除了"同一个东西五种样子"。

## 后果

- 页面工作量接近翻倍，由共享包与"先 PC 后手机、手机复用 PC 的数据钩子与业务组件"控制。
- 部署要构建三个应用并写入 nginx 的三个根目录；本机开发三个端口（5173 PC、5174 手机、5180 后台），刷新令牌 Cookie 与 WebSocket 的来源白名单都要包含它们与 `m.astras.vip`。
- Cookie 按主机隔离，PC 与手机各自登录。

## 备选

- 继续一个响应式站点：被否决，用户要两套。
- 原生 App 或 Tauri 桌面应用：被否决（2026-09-29 决定只做网页）。
- 引入完整 UI 框架（Ant Design、MUI 等）：被否决，体积大、视觉难以统一成交易所风格；Radix 只提供行为与可访问性。
