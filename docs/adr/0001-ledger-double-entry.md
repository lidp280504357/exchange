# ADR-0001：账本采用不可变双重记账，作为余额唯一事实来源

- 状态：已接受（2026-09-29）；"只追加、永不删除"由 [ADR-0022](0022-history-retention.md) 修订（2026-10-10）：保留工具可删除 15 天前的流水，删除的合计记为检查点、键留在键表，余额仍只由分录改变
- 关联：需求 §5.9、§11.4、§13 验收 4；决策 #3

## 背景

交易所的每一笔余额变化都可能被审计、对账和追责。常见的"直接 UPDATE 余额字段"模式在并发、重放和补偿场景下无法证明余额来源，出错后也无法重建。

## 决策

1. 所有余额变化只能通过账本分录（journal + journal_line）产生；分录只追加，不更新、不删除。
2. 一条 journal 内，同一资产的各 line 金额之和为 0；账户余额 = 该账户全部 line 的累加，`available` 与 `frozen` 分开记。
3. 系统科目（手续费收入、保险基金、待处理充值、待处理提现、资金费清算、做市、gas 补给、调账）与用户账户在同一账本内平衡；链上热/冷钱包余额不入账本，只作对账基准。
4. 写入以幂等键（业务事件 ID 或 trade_id）去重；重复消费同一事件不产生第二条分录。
5. 每小时增量、每日全量对账，任何不变量被破坏即暂停该资产提现并告警；人工纠错只能通过双人审批的 `MANUAL_ADJUSTMENT` 分录。

## 理由

可重放、可审计、可对账；并发安全由数据库唯一约束和事务保证，而不是应用层锁；出错时保留原始事件可以回放。

## 后果

- 查询余额需要维护 account 表上的余额快照（每条 line 写入后的 `available_after`/`frozen_after`）以避免全表求和。
- 撮合成交必须先生成事件再由账本消费，链路多一跳，但换来撮合与账本解耦。
- 分录表增长快，PostgreSQL 保留 1 年热数据，之后归档到 ClickHouse/对象存储并保留余额锚点。

## 备选

直接更新余额并记流水（被否决：流水与余额可能不一致，无法证明）；事件溯源全量重放（被否决：查询代价高，双重记账已满足审计要求）。
