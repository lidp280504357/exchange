# H5 前端

需求 §3、§6.6、§7；代码在 `web/h5`（React 19 + TypeScript + Vite 8、TanStack Query、Zustand、Tailwind CSS 4、react-i18next、openapi-fetch），阶段 1 页面：注册、登录（含 7 天登录验证）、忘记密码、资产与资金流水、交易对、划转、通知、登录设备与登录记录、设置（语言、防钓鱼码）；阶段 2 加入市场行情（`/markets`，实时 ticker）与交易页（`/trade/:symbol`）。

## 本机开发

```bash
task web:dev        # http://localhost:5173，/v1 与 WebSocket 由 Vite 代理到 https://astras.vip
task web:check      # API 类型与契约一致、类型检查、单元测试（task ci 也会跑）
task web:types      # 改了 api/openapi/*.yaml 后重新生成 src/api/gen（生成文件提交入库）
```

- 端口固定 5173：auth-service 的刷新 Cookie 只接受 `ALLOWED_ORIGINS` 里的来源（默认 `https://astras.vip,http://localhost:5173`），网关的 WebSocket 只接受 `WS_ORIGINS`（默认 `astras.vip,localhost:5173`）；换端口会刷新失败、推送连不上。代理到别的环境：`API_ORIGIN=https://... task web:dev`。
- Turnstile 站点密钥取仓库根目录 `.env` 的 `TURNSTILE_SITE_KEY`（公开值，只有它和 `VITE_*` 会进前端包，其余变量不会）。
- Claude Code 预览：`.claude/launch.json` 的 `h5` 配置用 nvm 里 node 的绝对路径直接启动 Vite（应用环境里没有 nvm 的 PATH），`autoPort: false`。首次启动若卡住没有日志，多半是 macOS 在等"访问桌面文件夹"的授权。

## 结构与约定

| 路径 | 内容 |
|---|---|
| `src/api/client.ts` | openapi-fetch 客户端（按服务一个）；`unwrap` 把统一错误体转成 `ApiError`（带 `code`、`details`、`trace_id`）；访问令牌过期（含账户状态变化后网关要求刷新）自动刷新并重试一次 |
| `src/api/gen/*.ts` | 由 `api/openapi/*.yaml` 生成的类型，CI 检查与契约一致 |
| `src/store/session.ts` | 会话：访问令牌只在内存；刷新令牌是 HttpOnly Cookie（`Path=/v1/auth/token/refresh`），页面看不到，所以另存一个"可能已登录"标记，匿名访问不发注定失败的刷新请求 |
| `src/lib/ws.ts` | `/v1/ws` 私有频道客户端：鉴权、订阅 `balances`/`notifications`/`orders`/`fills`、断线指数退避重连并带 `last_seq` 补发、令牌过期时刷新后重新鉴权 |
| `src/lib/market.ts` | 公共行情频道客户端（不鉴权，按需订阅/退订，重连后重新订阅）、深度簿（快照 + 增量，`prev_seq` 对不上就重新订阅拿快照）、用 BigInt 的精确乘法与百分比显示 |
| `src/pages/markets.tsx`、`src/pages/trade.tsx` | 市场列表；交易页：ticker、K 线（lightweight-charts，保留 TradingView 标识与链接）、盘口（点价格填入下单框）、最新成交、限价/市价下单、当前委托（撤单、全部撤单）、历史委托、成交记录 |
| `src/lib/decimal.ts` | 金额只按字符串处理（校验精度、比较、千分位），不转浮点（ADR-0008） |
| `src/i18n/` | 中文（默认）与英文；错误按错误码翻译（附录 C），接口枚举值按 `codes.*` 翻译 |
| `e2e/smoke.mjs` | 浏览器冒烟测试（见下） |

- 刷新：启动时若可能已登录就用 Cookie 换令牌，之后在过期前 1 分钟刷新；多个请求同时遇到过期只刷新一次；刷新遇到 `AUTH_TOKEN_EXPIRED`（另一个标签页刚轮换）等 1.5 秒重试一次。
- 写操作的幂等：划转为每次"想要的划转"生成一个 `Idempotency-Key`，网络错误后重试沿用同一个键，成功后才换新键。
- 敏感操作（退出其他设备、改防钓鱼码）弹出 step-up：发验证码到绑定邮箱，换 `X-Step-Up-Token` 后再调用。
- 余额、通知、订单与成交不轮询：WebSocket 推送到达时让对应查询失效重取；行情（ticker、盘口、成交、K 线）直接用推送更新。
- 下单每次生成新的 `Idempotency-Key`；撤单先在列表里显示"撤单中"，最终状态以引擎经 `orders` 推送为准。
- K 线只为画图把价格转成数字，不参与任何金额计算（ADR-0008）。
- PWA：`manifest.webmanifest` 与 192/512 px 图标（可"添加到主屏幕"）；离线缓存的 Service Worker 暂不做，避免部署后页面被旧缓存卡住。

## 部署

`deploy/server-update.sh` 每次部署在 `node:24-slim` 容器里 `pnpm install --frozen-lockfile && pnpm build`（pnpm 缓存在命名卷 `exchange-pnpm-store`，Turnstile 站点密钥取自服务器 `apps.env`），构建最后一步 `scripts/build-docs.mjs` 把 `api/openapi/*.yaml` 合并成 `dist/docs/openapi.json` 并生成 Redoc 页面（`https://astras.vip/docs/`，合并冲突会让构建失败）。构建成功后把 `web/h5/dist/` 同步到 `/opt/exchange/infra/nginx/html/` 并替换旧文件。nginx（`deploy/compose/nginx/snippets/site-locations.conf`）：

- `/assets/*` 文件名带哈希，`Cache-Control: public, max-age=31536000, immutable`；
- `index.html` 与其余路径 `Cache-Control: no-cache`，未知路径回退到 `index.html`（前端路由）；
- `manifest.webmanifest` 以 `application/manifest+json` 返回。

回滚与后端一起：`task deploy -- <提交号>` 会用那个提交的前端重新构建。

## 测试

- 单元测试（Vitest）：`pnpm test`，覆盖金额处理与 API 客户端（错误映射、过期刷新重试、并发只刷新一次、登录与刷新竞争）。
- 端到端：`scripts/e2e/h5.sh`（`task e2e` 一起跑）先检查静态站点（SPA 回退、缓存头、manifest），再用无头 Chrome 跑 `web/h5/e2e/smoke.mjs`：通过 API 注册用户后，以手机尺寸在页面上登录（含错误密码提示）、看欢迎资金、表单划转（含超精度拦截）、另一会话划转后余额经 WebSocket 实时更新、交易对、在交易页挂一笔远低于市价的限价买单（盘口与当前委托出现）再撤掉（两处都消失）、通知、登录设备、刷新页面恢复会话、设置、退出。需要本机 Chrome（或 `CHROME=` 指定路径），没有则跳过浏览器部分；`SHOTS=/tmp/shots` 保存截图。对本机开发服务器：`BASE=http://localhost:5173 scripts/e2e/h5.sh`。
