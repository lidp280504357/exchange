## 1. 分层

```
后台「价格事件」 / scripts/ops/price-event.sh
        │  POST /admin/v1/sim/events（admin 键）  /  exchangectl sim call（ops 键）
        ▼
market-sim：事件（类型 OVERLAY）——校验、守卫预算、HOUSE 损失上限、按秒算乘数 f(t)、存库与重启续推
        │  每秒 PUT /internal/market/overlay/{symbol}（svcsign，键 sim）
        ▼
market-data：叠加层——参考盘口、参考成交、ticker、K 线、sparkline/summary × f；risk 时现货指数用叠加价、
             该现货对的永续标记价改为自算并同乘参考簿
        │  market.depth（带 overlay_factor）、market.trades、ticker、指数/标记价……
        ▼
market-maker：照叠加后的参考簿报价，overlay_factor ≠ 1 时每档数量 × OVERLAY_QUOTE_FRACTION
引擎、账本、derivatives-service、margin-service：不知道有叠加（成交价、标记价就是它们看到的）
```

平台币（没有参考市场的交易对，ASTRA-USDT）的事件仍是 market-sim 现有的价格模型事件（`TARGET`），由同一个入口按交易对路由（§3.2）。

## 2. market-data：叠加接口（J1 实现）

内部接口，只在 compose 网络（网关不转发 `/internal`），改动要 `svcsign` 签名：键 ID `sim`，密钥 `OVERLAY_API_SECRET`（market-data 与 market-sim 各一份，部署脚本首次生成 `market/overlay.env`，同 C47 的做法；缺了或不足 32 个字符时改动一律 401、读照常）。

### 2.1 `PUT /internal/market/overlay/{symbol}`

```json
{"factor": "1.16", "until": "2026-10-07T02:00:15Z", "risk": true, "event_id": "0192…", "seq": 17}
```

| 字段 | 含义 |
|---|---|
| `factor` | 十进制字符串，乘数 f(t)；0.1 ≤ f ≤ 1.9（守卫的硬上限 ±90%），"1" 即不叠加 |
| `until` | 这个乘数最晚用到何时：market-sim 每秒推一次、`until` 取下一次推送之后 4 秒以内；过了 `until` 或 5 秒没有推送（以收到的时间计）→ 回到 1 |
| `risk` | `true`（默认，用户 03:0x 决定）：该现货对是指数价源的永续——指数用叠加价、标记价来源在事件期间改为自算（`PLATFORM`）、永续的参考簿同乘；`false`：只叠加现货显示与成交，永续与杠杆看到币安原价 |
| `event_id`、`seq` | 来自哪个事件与第几次推送；`seq` 小于已收到的同一事件的就丢弃（乱序） |

答 204。`symbol` 是跟随参考市场的现货交易对（`BTC-USDT`）；不是的 409 `MARKET_NOT_FOLLOWED`；开关 `market.overlay` 关着 409 `MARKET_OVERLAY_OFF`；同一交易对正有另一个事件的叠加（`event_id` 不同、乘数未回到 1）409 `MARKET_OVERLAY_BUSY`。

### 2.2 `DELETE /internal/market/overlay/{symbol}` 与 `GET /internal/market/overlay`

- `DELETE`：立刻回到 1（运维的急停；平缓的"立即恢复"由 market-sim 用 3 秒的回落推送完成），204。
- `GET`：`{"items": [{"symbol", "factor", "until", "risk", "event_id", "seq", "updated_at"}]}`，只列乘数 ≠ 1 的；不要签名。

### 2.3 作用（乘数 ≠ 1 的交易对；J1）

| 数据 | 怎么变 |
|---|---|
| 参考盘口（`market.depth`，HOUSE 照它报价） | 每档价格 × f，买价向下、卖价向上取到价格步长（不比原价让利），落在同一格的合并，数量不变；乘数在变（爬升、回落）时每次推送发快照而不是增量；消息带 `overlay_factor`（§5） |
| 参考成交（`market.trades`）与由它生成的 K 线 | 价格 × f（按步长取整），数量不变；历史 K 线不改；突刺留在 K 线里 |
| ticker、sparkline、summary | 用叠加后的成交重算：最新价、24 小时高低（含事件期间的值）与涨跌 |
| 内网参考价 `GET /internal/market/{symbol}/reference` | 叠加后的价格（交易服务的价格带与市价保护价锚点随之） |
| 指数价（`risk`） | 该现货对作价源的永续，指数用叠加后的现货价 |
| 标记价（`risk`） | 这些永续的标记价来源在乘数 ≠ 1 期间强制自算（`PLATFORM`，即使开关 `market.reference_mark` 对它开着），回到 1 后 30 秒恢复原来源；永续的参考簿同乘 |
| 资金费率（`risk`） | 自算的标记价照常进入溢价指数，与真实行情一样 |

`risk=false` 时以上后三项不变（永续盘口、指数、标记价都是币安原价；现货与永续价格不一致是选择这一项的代价，后台表单常驻提示）。

### 2.4 开关、指标、告警

- 开关 `market.overlay`（全局，默认关）：关掉时所有乘数立刻回到 1，`PUT` 答 409。
- 指标 `market_overlay_factor{symbol}`（乘数 ≠ 1 的交易对；回到 1 时删除该序列）、`market_overlay_pushes_total{result}`（`ok`、`stale`、`refused`）。
- 告警 `MarketOverlayStuck`：乘数 ≠ 1 持续超过 11 分钟（事件最长 10 分钟加 1 分钟）。

## 3. market-sim：通用事件（J2 实现）

### 3.1 创建：`POST /internal/sim/events` 新类型 `OVERLAY`

```json
{"type": "OVERLAY", "symbols": ["BTC-USDT"], "target_price": "100000", "ramp_up_seconds": 15, "hold_seconds": 0,
 "ramp_down_seconds": 5, "risk": true, "starts_at": "2026-10-07T02:00:00Z",
 "actor": "admin:ops@example.com", "approved_by": "", "reason": "演示突刺"}
```

| 字段 | 规则 |
|---|---|
| `symbols` | 1–10 个交易对；跟随参考市场的（叠加）与平台币的（价格模型）可以混填，按交易对分别建事件（§3.2） |
| `target_price` 或 `target_pct` | 二选一：绝对价格（十进制字符串），或相对开始时币安价的百分比（`16` 为 +16%、`-20` 为 −20%）；多个交易对时只能用 `target_pct` |
| `ramp_up_seconds` | ≥ 1，到达目标用时 |
| `hold_seconds` | ≥ 0，保持 |
| `ramp_down_seconds` | ≥ 3，回到币安价用时（平台币的事件忽略） |
| 合计 | ≤ `OVERLAY_MAX_SECONDS`（600，硬上限） |
| `risk` | 默认 `true`（连带合约与杠杆）；`false` 即后台的「不连带」 |
| `starts_at` | 可选，默认立即；最晚 24 小时内 |

乘数路径：开始时取币安价 P₀（参考成交的最新价），目标乘数 F = 目标价 ÷ P₀；f(t) 在 `ramp_up` 内从 1 线性升到 F，`hold` 内保持 F，`ramp_down` 内线性回到 1。因为乘的是币安的实时价，事件期间币安自己的涨跌叠加在上面，回到 1 即与币安一致、不留偏差。

答 201：`{"items": [{"symbol", "event_id", "type", "status", "factor_target", "base_price"}]}`（`status` 为 `SCHEDULED` 或 `RUNNING`）。

错误：

| 码 | 何时 |
|---|---|
| `SIM_EVENT_NEEDS_APPROVAL`（403，已有） | 超出单人份额（守卫预算按交易对、按生效时间的任意一小时：单人 30%、批准后 50%）而没有 `approved_by` |
| `SIM_APPROVAL_NEEDS_ADMIN`（403，已有） | `approved_by` 不是 admin 键签的 |
| `SIM_OVERLAY_RUNNING`（409） | 该交易对已有未结束的 `OVERLAY` 事件（每个交易对同时一个） |
| `SIM_OVERLAY_TOO_FAR`（400） | 偏离超过硬上限 ±90%（F 不在 0.1–1.9） |
| `SIM_OVERLAY_LOSS_CAP`（409） | HOUSE 最坏损失估算超过 `OVERLAY_MAX_LOSS_USDT`（§3.3），`details` 带估算值与上限 |
| `SIM_OVERLAY_OFF`（403） | 开关 `market.overlay` 关着 |
| `SIM_NOT_OVERLAYABLE`（400） | 交易对既不跟随参考市场、也不是平台币 |
| `COMMON_INVALID_ARGUMENT` | 其余格式问题 |

### 3.2 平台币的路由

`symbols` 里的平台币交易对建成现有的 `TARGET` 事件：目标价同上换算（`target_pct` 相对它当前的模型价），窗口 = `ramp_up_seconds`，`hold_seconds` 照用，`ramp_down_seconds` 与 `risk` 不适用；守卫与现在相同。

### 3.3 HOUSE 损失上限

事件开始前（与每个交易对各算一次）：
- 向上（F > 1）：用户会把基础币卖给 HOUSE 的高价买单，回落后 HOUSE 亏 `买入额 × (1 − 1/F)`；最坏按 HOUSE 在该交易对此刻的买入额度（USDT）算。
- 向下（F < 1）：用户低价从 HOUSE 买走，HOUSE 亏 `卖出数量 × P₀ × (1 − F)`；最坏按此刻的卖出额度算。
- 额度读 market-maker 新的只读内部接口 `GET /internal/house/rooms/{symbol}`（§4.2）；读不到就拒绝（`SIM_OVERLAY_LOSS_CAP`，`details.reason`）。
- 测试服 `OVERLAY_MAX_LOSS_USDT` 为 200,000；事件期间 HOUSE 每档只报 `OVERLAY_QUOTE_FRACTION`（25%），实际敞口小于估算。

### 3.4 运行、结束与恢复

- 调度每秒算一次 f(t)，推给 market-data（§2.1）；推送失败下一秒重推，market-data 5 秒收不到就自己回 1。
- 结束：`POST /internal/sim/events/{id}/end`（已有）对 `OVERLAY` 即"立即恢复"——从当前乘数用 3 秒线性回到 1，状态 `DONE`、`result` `CANCELED`、`ended_by` 记操作人；开关 `market.overlay` 关掉时 market-data 立刻回 1，market-sim 把运行中的叠加事件记为 `CANCELED`。
- 重启：market-sim 启动后按库里 `RUNNING` 与到时的 `SCHEDULED` 事件从当前时刻续推（路径按事件自己的时间表算，不从头开始）。
- 完成时记下实际路径的抽样：`base_price`（P₀）、`peak_price`（平台峰值）、`end_reference_price`、`end_platform_price`（回到 1 后第一次推送时的币安价与平台价）。
- 列表 `GET /internal/sim/events`（已有）给 `OVERLAY` 事件加 `symbol`、`target_factor`、`factor_now`、`progress`（0–1）、`risk` 与上面四个抽样价。

### 3.5 运维

`scripts/ops/price-event.sh start SYMBOL... (--price P | --pct N) --up S [--hold S] --down S [--no-risk] "原因"`、`stop ID`、`list`，经 market-sim 容器里的 `exchangectl sim call`（`ops` 键，单人份额内）。

## 4. 其它服务

### 4.1 market-maker（J1）

- 参考簿消息的 `overlay_factor`（§5）不为空且不为 "1" 时，HOUSE 每档数量 × `OVERLAY_QUOTE_FRACTION`（默认 0.25，0 < x ≤ 1），取整到数量步长；额度规则不变（买够了照样停买）。
- 指标 `market_house_overlay_quoting{symbol}` 为 1 表示正在减量报价。

### 4.2 market-maker 只读接口（J2 用）

`GET /internal/house/rooms/{symbol}` → `{"symbol", "buy", "sell", "mid", "unit_value", "updated_at"}`：HOUSE 此刻在该交易对或合约还能买、卖的数量（基础币或张），参考中价，每单位的 USDT 价值；没有在报价时 404。不签名（只读，内网）。

### 4.3 后台（J3，后台会话）

`api/admin/admin.yaml` 的 `/admin/v1/sim/events`：创建的正文照 §3.1（另有 `approval_id`）；列表与详情的事件项加 §3.4 的字段；`/admin/v1/sim/events/{id}/end` 对 `OVERLAY` 即立即恢复。契约在 J2 与接口一起提交，后台会话据此做页面。
