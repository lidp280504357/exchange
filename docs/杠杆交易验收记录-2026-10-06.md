## 1. 结论（站点部分）

E4 的出口标准"两站流程全绿"满足：上线检查清单流程（含新加的杠杆项 P9、M7）在两站与后台全部通过，浏览器冒烟覆盖杠杆的开通路径与推送契约。设计 §12.1 的预算在杠杆账户页与交易页的杠杆模式下全部满足（全量 `task web:perf` 无未达标项）：首屏 JS 按入口口径（审查 DV）为 159 / 147 KB；首屏前拉取的全部 JS 只作对照，杠杆账户页低于资产总览，见 §2.3。

- 同次运行的其它 §12.1 运行时项全部达标，杠杆改动没有带来回归：终端推流一分钟长任务 0 / 0；盘口重绘 p95 13 / 14 ms；每条深度消息到显示它的帧 p95 239 / 234 ms（最大 256 / 257）；成交消息到成交带 p95 27 / 30 ms；切换交易对 18 / 22 ms；离开再回到终端 34 / 55 ms，不新建连接、不重收快照；手机行情列表与 1000 行表格 60 fps。
- 口径（审查 DV ③，B114）：首屏 JS 预算按入口 JS 判定，与 B3 记录的"首屏入口 JS（`index.html` 引用的入口与预加载）"同一口径（B2/B3 时为 142 / 143 KB）。路由预加载（`web/scripts/route-preload.mjs` 按打开的地址额外插入的链接）不计入入口，单列：杠杆账户页没有登记路由预加载，资产总览有。若把路由预加载也算进入口，资产总览为 297 / 267 KB，超出预算；这与杠杆无关，口径由协调会话定。首屏前拉取的全部 JS 只作对照：已登录的资产类页面都超过 250 / 200 KB（资产总览 304 / 272 KB），杠杆账户页（276 / 236 KB）低于资产总览。
- 归因（审查 DV ①）：13:14 在 58d1e667 部署之前测得首屏前的全部 JS 为 339 / 299 KB，首屏文件里有弹窗的表单组件（Form、Select、NumberInput）；14:14 在 432bb8c（含 58d1e667，弹窗改为按需加载）上为 276 / 236 KB。降幅来自按需加载；3bf03ac8 的提交说明把它归于空闲预载，有误。
- 空闲预载（B108；B114 起先等 load 事件）：load 之后浏览器空闲时请求（`requestIdleCallback`，最多 3 秒；没有它的浏览器如 iPhone Safari 在 load 之后 3 秒，B114 之前是固定 1.5 秒，可能落在首屏里）。杠杆账户页的 load 早于账户接口返回，所以预载在账户卡片出现前约 0.5 秒发出，不占首屏的主线程；测量按 modulepreload 链接的批次认出这批块（同一次动态导入一并请求的块），从首屏 JS 里剔除并单列。重新加载交易页那一行的块来自本次会话早些时候的 HTTP 缓存，所以一发出就到齐。
- 弹窗第一次打开（B114、B115）：在 fbaa1ba（B114 之前）上，块已到齐时第一次打开仍要 329–351 ms（两站、经链接进入与重新加载都一样）：`React.lazy` 在块已加载时也会在首次渲染挂起，React 19 让 Suspense 的内容在 fallback 出现 300 ms 之后才显示。ui 的 `preloadable` 在预载完成后让 `React.lazy` 的导入立即兑现、渲染时不挂起（B115 起每个块一个实例、杠杆页与交易页共用，元素类型始终同一个，导入失败后换新的 lazy 组件），现为 19–30 ms。B114 之前的脚本在切到全仓 2.5 秒后就点"借币"，块可能还没到（14:14 测得 969 / 1009 ms，是块的下载加上这 300 ms）；现在先等这批块到齐再点（审查 DV ⑤）。
- 测量机到测试服往返约 380 ms，LCP 含这段网络时间；切换、路由与弹窗是在数据已缓存时测的，不含网络。

### 2.4 已知限制

- 余额推送 `balances` 与 `GET /v1/account/balances` 不含杠杆账户：杠杆账户的余额只经 `margin` 频道的账户快照与 `GET /v1/margin/accounts` 到达。
- 账户快照不补发：断线期间的变化由重连后的一次重拉补上，没有负债的账户在只有价格变化时不推送，估值靠每 15 秒的刷新。
- 杠杆对用户关闭后，遗留的杠杆资产只在访问过资产总览（入口探测取到账户）之后才计入首页与"我的"的总资产。
- 资产分布环只按现货与合约的币种（杠杆净额可为负，不进环）。
- 逐仓倍数标记对所有访客显示（与币安一致）；上线前若暂不开放杠杆，标记仍会显示交易对支持的倍数。

| 计息 | 固定与浮动两种模型（浮动按池利用率的拐点曲线）；整点后 30 秒按整点本金计一小时，借币时首小时随借款一笔；一次快照读借款与变动，每 (资产, 小时) 的应计集合只存一次、每个账本分录至多 1000 个账户（键 `<资产>:<整点>[:<n>]`），重试按存下的集合；租约 `margin-interest`；超过 48 小时未记的由恢复补记 |

| 强平（E3） | `CANCEL → SELL → FEE → BUY → REPAY → COVER → SETTLE`，每步记在 `liquidations`、重启后接着做。订单按交易对与方向编号 `attempt`（迁移 margin 00007），先存后发、同一单再发只读回，成交只认交易服务报的终态与 `filled_*`，带 `order_id` 的拒绝即该单终态；按估值从大到小只卖到够还负债、买回与强平费再多 2%，没卖够的下一轮以 `attempt + 1` 续卖（无成交时退避，最多 1 分钟），交易对暂停时等待；强平费 = 2% ×（卖出所得 + 将买入额），先于买入，按与 BUY 步同样的规则计；被拒的强平还款重算后换键再还；保险基金只补"负债 − 可用"，某资产不足时记 `SHORTFALL`、负债保留并告警。自动强平受 `margin.liquidation` 控制；手工强平经后台第二人批准（内部接口带 `approval_id`）或 `exchangectl margin liquidate` |

| 对账 | 不变量 7（账本负债行 = 借款表）与池子（已借出 = 借款 + 在途、不超上限），每小时一次并可 `exchangectl margin reconcile`，不一致的复查一次再报 |
| 事件与契约 | `margin.events`：`MarginLevelWarned`、`MarginLiquidationStarted`（含 `trigger`、`approval_id`）、`MarginLiquidationCompleted`（含 `margin_level`、`total_asset`、`total_liability`、`started_at`）等；`margin.accounts` 的账户快照 |

- 自动还款经 `ledger.events` 回到借款表；事件晚于整点计息（整点后 30 秒）才到时，那一小时可能按还款前的本金计息（对账有 1 分钟宽限）。
