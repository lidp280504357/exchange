## 3. 下单与两个服务之间的接口

### 3.1 对外（`api/openapi/trading.yaml`）

`POST /v1/orders` 新增 `account`：`SPOT`（默认）| `MARGIN_CROSS` | `MARGIN_ISOLATED`（交易对的逐仓账户），`side_effect`：`NONE`（默认）| `AUTO_BORROW` | `AUTO_REPAY`；`Order` 带回这两个字段。E2 之前只接受 `SPOT` 与 `NONE`。

### 3.2 下单流程（E2；本会话做 spot-trading-service 一侧，杠杆后端会话做 margin-service 一侧）

1. spot-trading-service 照常校验交易对、精度、名义额、价格带，算出冻结的资产与数量（买冻结计价资产，卖冻结基础资产）。
2. `account` 为杠杆账户时调 margin-service 的 gRPC `MarginService.ReserveOrder`（`api/proto/exchange/margin/v1/margin.proto`）：开关、账户状态、资产归属、可用 + 可借 ≥ 冻结额、借后风险率不低于预警线；`AUTO_BORROW` 时在账户锁内借入差额（`MARGIN_BORROW`，首小时利息同时计）。按 `order_id` 幂等。`CheckOrder` 是同样的检查但什么都不改，留给预览与排查用。
3. spot-trading-service 再调账本冻结，账户为杠杆资产行（`account_type` = MARGIN_CROSS / MARGIN_ISOLATED，逐仓带 `scope` = 交易对），之后与现货单一样送撮合。冻结失败（并发下单抢了余额）时订单记 REJECTED，已借的不自动还。
4. 撮合不看账户；订单命令与订单事件里的 `exchange.order.v1.Order` 带 `account_type`、`side_effect`（字段 21、22），成交事件 `TradeExecuted` 带 `buyer_account_type` / `seller_account_type` / `buyer_side_effect` / `seller_side_effect`（字段 20–23，HOUSE 一侧为空）。
5. 账本按成交的账户结算：用户一侧在杠杆账户记 `MARGIN_TRADE_SETTLE`（HOUSE 一侧照旧 `MARKET_MAKER`）。
6. `AUTO_REPAY`：margin-service 消费 `trade.events`，看到己方 `side_effect` 为 `AUTO_REPAY` 的成交后，用成交得到的资产还该资产的负债（`MarginRepaid`，`reason` = AUTO_REPAY）。

### 3.3 要杠杆后端会话在账本一侧加的（`ledger.proto` 与账本代码归它）

- `FreezeRequest`、`UnfreezeRequest`、`PlaceHoldRequest` 加 `string scope`（逐仓账户的交易对；其它为空），`account_type` 接受 MARGIN_CROSS / MARGIN_ISOLATED；冻结记录（holds）记下账户与 `scope`，结算与解冻按它找账户。
- 交易结算读成交事件的双方账户字段，杠杆账户记 `MARGIN_TRADE_SETTLE`。

### 3.4 强平市价单（E3；本会话做 spot-trading-service 的内部接口）

margin-service 强平时调 spot-trading-service 的内部接口（只在内网，不经网关）：

```
POST /internal/orders/liquidations
{ "liquidation_id": "<uuid>", "user_id": "<uuid>", "account": "MARGIN_CROSS | MARGIN_ISOLATED",
  "symbol": "BTC-USDT", "side": "SELL", "quantity": "0.5" }          // 买入时给 quote_amount
→ 202 { "order_id": "<uuid>" }
```

市价单对 HOUSE 成交，绕过下单限流、价格带与 `margin.enabled` 检查（账户已被冻结，强平是唯一的出路），按 `liquidation_id` + 交易对 + 方向幂等；成交照常经 `trade.events` 回到账本与 margin-service。与合约的强平路径同构。

## 7. 账本（草案迁移 `migrations/ledger/00008_margin.sql`，E1 落地）

### 7.1 记法：负债记成负数行（协调会话 2026-10-06 01:15 定；01:23 定利息在计息时直接记收入）

设计稿 §3.2 的写法——借币时"用户 `balance`、`borrowed` 同增，HOUSE `MARGIN_LENDING` 同增"——在本账本里记不平：每个分录按资产合计必须为 0（触发器 `journal_lines_balanced`），三行同为正数合计是 3a。草案的记法：

- 用户杠杆账户每资产三行：资产行 `MARGIN_CROSS`（可用 + 冻结，≥ 0）、负债行 `MARGIN_CROSS_DEBT`（本金，记为负数）、利息行 `MARGIN_CROSS_INTEREST`（应计未还利息，记为负数）。逐仓同样三种（`MARGIN_ISOLATED`、`MARGIN_ISOLATED_DEBT`、`MARGIN_ISOLATED_INTEREST`），以新列 `scope` 记交易对；其它账户的 `scope` 为空。对外仍称 `MARGIN_ISOLATED:<symbol>`。
- 借出方 HOUSE 不另设"已借出"账户：借币时资产行 +a、负债行 −a，在用户自己的账户内记平；HOUSE 已借出（`MARGIN_LENDING`）= −Σ 负债行（按资产），不单独记账；池余量 = 池上限 − 已借出。
- 系统账户新增 `MARGIN_INTEREST_INCOME`（HOUSE 的利息收入，计息时确认）。01:10 曾定另设应收利息 `MARGIN_INTEREST_RECEIVABLE`、还息时才转收入，01:23 改回本稿：少一个科目、每笔分录少两条腿；未还利息由用户的利息行体现，穿仓时由保险基金补足。强平费直接记 `INSURANCE_FUND`（合约保险基金，设计稿 §11 已定共用；不设 `MARGIN_LIQ_FEE_INCOME`），穿仓补足也从它出。

| 分录类型 | 分录行（同一资产内合计为 0） |
|---|---|
| `MARGIN_TRANSFER_IN` / `OUT` | 用户 `SPOT` ∓a，用户杠杆资产行 ±a |
| `MARGIN_BORROW` | 杠杆资产行 +a，负债行 −a |
| `MARGIN_INTEREST` | 每个账户利息行 −I，HOUSE `MARGIN_INTEREST_INCOME` +ΣI（按资产一笔汇总，每账户一行明细） |
| `MARGIN_REPAY` | 杠杆资产行 −(I+P)，利息行 +I，负债行 +P（I 为本次还的利息，先还利息再还本金；只在用户账户内平衡） |
| `MARGIN_TRADE_SETTLE` | 同 `HOUSE_TRADE_SETTLE`，只是用户一侧是杠杆资产行（下单冻结沿用 `ORDER_FREEZE` / `ORDER_UNFREEZE`，账户为杠杆资产行） |
| `MARGIN_LIQUIDATE` | 强平卖出后的还款（同 REPAY）、强平费（杠杆资产行 −f，`INSURANCE_FUND` +f）、穿仓补足（`INSURANCE_FUND` −s，负债行或利息行 +s） |

### 7.3 不变量 7–9 的对账（`exchangectl ledger reconcile` 新增，E1）

按 §7.1 的记法改写：

7. **负债与借款簿一致**：账本每个（用户、账户、`scope`、资产）的 −负债行 = margin-service 借款表 `margin.loans.principal`，−利息行 = `margin.loans.interest`；按资产 −Σ负债行 ≤ 池上限。账本这一侧：
   ```sql
   SELECT owner_id AS user_id, account_type, scope, asset, -available AS owed
   FROM accounts
   WHERE account_type IN ('MARGIN_CROSS_DEBT', 'MARGIN_ISOLATED_DEBT', 'MARGIN_CROSS_INTEREST', 'MARGIN_ISOLATED_INTEREST')
     AND available <> 0;
   ```
   margin-service 提供同样形状的内部接口，对账逐行比较（与合约的不变量 6 同样跨服务）。
8. **利息守恒**：每个 `MARGIN_INTEREST` 分录里，HOUSE 收入行 = −Σ 用户利息行（按资产）；HOUSE `MARGIN_INTEREST_INCOME` 余额 = 历史计息之和：
   ```sql
   SELECT l.asset,
          sum(l.amount) FILTER (WHERE a.account_type = 'MARGIN_INTEREST_INCOME') AS income,
          -sum(l.amount) FILTER (WHERE a.account_type IN ('MARGIN_CROSS_INTEREST', 'MARGIN_ISOLATED_INTEREST')) AS accrued
   FROM journal_lines l JOIN journals j ON j.id = l.journal_id JOIN accounts a ON a.id = l.account_id
   WHERE j.entry_type = 'MARGIN_INTEREST'
   GROUP BY l.asset
   HAVING sum(l.amount) FILTER (WHERE a.account_type = 'MARGIN_INTEREST_INCOME')
       <> -sum(l.amount) FILTER (WHERE a.account_type IN ('MARGIN_CROSS_INTEREST', 'MARGIN_ISOLATED_INTEREST'));
   ```
   未还利息 = −Σ 利息行 = 历史计息 − 已还利息。
9. **符号**：资产行 ≥ 0，负债行与利息行 ≤ 0（上面的约束保证，对账再查一次并报告），HOUSE 已借出 ≤ 池上限（margin-service 每次借币时检查，对账复核）。

## 11. 服务
