## 1. 需求（用户确认）

1. 产品形态与币安杠杆交易一致：独立的杠杆账户，借币后在现货交易对上买卖，按小时计息，到期无强制还款，风险率过低预警、强平。
2. **全仓**（一个账户，多币种资产与负债互相覆盖）与**逐仓**（每个交易对一个账户，只含该对的两种资产）都做。
3. **倍数与币安一致**：全仓 3 倍（后台可放开到 5 倍）；逐仓按交易对 3 / 5 / 10 倍（后台按交易对配置，默认见 §4.2）。
4. **币种**：第一批可借与可作保证金的资产为 USDT、BTC、ETH，加 BNB、SOL、XRP、DOGE、ADA 等主流币（最终名单在 `deploy/instruments/test.json` 里按资产标记），以及平台币 ASTRA。
5. **利率模型两种都要**：固定小时利率（后台按资产设置）与浮动利率（按借贷池利用率），后台按资产选用哪一种。
6. 强平线与强平费：用户决定按行业做法——采用币安的风险率阈值与 2% 强平费（§4.4），后台可调。

与项目前提一致：学习项目、模拟资金、所有交易对手方是 HOUSE（ADR-0013/0015）。因此**借出方就是 HOUSE**，不需要真实的放贷用户与借贷池撮合；"借贷池"只是 HOUSE 为每种资产配置的可借上限。

## 2. 名词与核心模型

| 名词 | 定义 |
|---|---|
| 杠杆账户 | 与现货账户分开的账本账户：`MARGIN_CROSS`（全仓，一个）与 `MARGIN_ISOLATED:<symbol>`（逐仓，每交易对一个，首次划入时创建） |
| 资产 / 负债 | 账户内每种资产的余额（可为冻结与可用）与负债（借入本金 + 应计利息）；负债只能通过借币与计息增加、通过还币与强平减少 |
| 估值 | 一律折成 USDT：用平台该交易对的最新成交价（内部市场）或币安 ticker（跟随行情的交易对），与合约指数价同源；没有价格的资产不计入资产、按最保守方式计入负债 |
| 总资产 / 总负债 | 账户内全部资产估值之和 / 全部负债估值之和 |
| 风险率（margin level） | 总资产 ÷ 总负债；无负债时记为 ∞（显示 999） |
| 净资产（equity） | 总资产 − 总负债 |
| 可借额度 | min（净资产 × (倍数 − 1) − 已借，资产可借池余量，单用户上限）按估值折算成该资产数量 |
| 倍数 | 全仓账户级（默认 3）；逐仓交易对级（默认见 §4.2） |
| 预警线 / 强平线 | 风险率阈值（§4.4）；低于预警线发通知，低于强平线由系统强平 |
| 强平 | 系统冻结账户、撤销全部挂单、以市价对 HOUSE 平掉仓位并归还负债，收取强平费，剩余归还用户；资产不足以还债的部分由保险基金承担 |

## 3. 账本（硬规则：余额只能经账本分录改变，ADR-0001）

### 3.1 账户与科目

- 用户：`MARGIN_CROSS`、`MARGIN_ISOLATED:<symbol>`，每账户每资产两行：`balance`（资产，≥ 0）与 `borrowed`（负债本金，≥ 0）、`interest`（应计未还利息，≥ 0）。
- HOUSE：`MARGIN_LENDING`（各资产已借出余额，= Σ 用户 `borrowed`）、`MARGIN_INTEREST_INCOME`（已收利息）、`MARGIN_LIQ_FEE_INCOME`（强平费，转入保险基金 `INSURANCE`，复用合约的保险基金科目与双人审批）。
- 借贷池上限是配置（§4.1），不是账户余额：HOUSE 的可借出余量 = 上限 − `MARGIN_LENDING`。

### 3.2 分录类型（`ledger.entry_type` 新增）

| 类型 | 动作 | 不变量 |
|---|---|---|
| `MARGIN_TRANSFER_IN` / `MARGIN_TRANSFER_OUT` | 现货账户与杠杆账户之间划转；划出后风险率不得低于预警线，且不得划出被负债占用的资产 | 现货 + 杠杆总额守恒 |
| `MARGIN_BORROW` | 借入：用户 `borrowed`、`balance` 同增；HOUSE `MARGIN_LENDING` 同增 | 借后可借额度 ≥ 0，池余量 ≥ 0 |
| `MARGIN_INTEREST` | 每小时计息：用户 `interest` 增加；不动 `balance` | 利息按 §4.3 公式逐笔可复算 |
| `MARGIN_REPAY` | 还币：先还 `interest` 再还 `borrowed`；用户 `balance` 减少，HOUSE `MARGIN_LENDING` 减少、`MARGIN_INTEREST_INCOME` 增加 | 还款不超过负债 |
| `MARGIN_TRADE_SETTLE` | 杠杆账户上的成交结算：与 `HOUSE_TRADE_SETTLE` 同构，只是账户是杠杆账户 | 与现货结算同一套对账 |
| `MARGIN_LIQUIDATE` | 强平：系统市价成交后的还款、强平费、剩余归还、穿仓时保险基金补足 | 强平后账户负债为 0 |

### 3.3 不变量（`exchangectl ledger reconcile` 新增）

7. Σ 用户 `borrowed` = HOUSE `MARGIN_LENDING`（按资产）。
8. Σ 用户 `interest` + `MARGIN_INTEREST_INCOME` = Σ 历史 `MARGIN_INTEREST` 分录（按资产）。
9. 任一杠杆账户 `balance`、`borrowed`、`interest` 均 ≥ 0；HOUSE 可借出余量 ≥ 0。

## 4. 借贷、计息与风控参数

### 4.1 资产参数（后台「杠杆参数」页，按资产）

| 参数 | 默认 | 说明 |
|---|---|---|
| 可借 / 可作保证金 | 两者都开（名单内资产） | ASTRA 建议：可作保证金、可借但上限低（§11） |
| 借贷池上限 | USDT 2,000,000；BTC 20；ETH 400；主流币按 50 万 USDT 等值；ASTRA 按 10 万 USDT 等值 | HOUSE 的模拟供给；测试服与正式环境的值写在 `test.json`/正式 instruments 文件 |
| 单用户可借上限 | 池上限的 10% | |
| 利率模型 | `FIXED` 或 `FLOATING` | 按资产选 |
| 固定小时利率 | USDT 0.0010%/h（≈ 8.76%/年）；BTC/ETH 0.0005%/h；主流币 0.0015%/h；ASTRA 0.0030%/h | 币安同量级 |
| 浮动模型 | 基准 0.0005%/h + 斜率；利用率 ≤ 80% 时线性升到 0.0030%/h，80% 以上陡升到 0.0100%/h | 利用率 = 已借出 ÷ 池上限，每小时取整点时刻的值 |
| 保证金折扣（haircut） | USDT 1.00；BTC/ETH 0.95；主流币 0.90；ASTRA 0.70 | 计算总资产时乘以折扣，防止薄市资产被高估 |

### 4.2 交易对参数（逐仓）

| 参数 | 默认 |
|---|---|
| 逐仓倍数 | BTC-USDT、ETH-USDT 10 倍；其它主流币对 5 倍；ASTRA-USDT 3 倍；以 BTC 计价的交易对 3 倍 |
| 全仓倍数 | 账户级 3 倍（后台可改 5 倍，改动走双人审批） |

### 4.3 计息规则（与币安一致）

- 借入即计第一个小时的利息；之后每个整点按当时未还本金计一小时（`利息 = 本金 × 小时利率`），利息累入负债但不复利（利息本身不再计息）。
- 浮动模型按整点时刻的利用率取当小时利率，并记录在分录里，便于复算。
- 还款先抵利息、再抵本金；部分还款允许。
- 计息由 margin-service 的定时任务执行（每小时整点，带租约主备，失败重试；按资产一笔汇总分录 + 每账户明细）。

### 4.4 风险率阈值与强平费（默认值，待用户确认；后台可调，改动走双人审批）

| 账户 | 预警线 | 强平线 | 说明 |
|---|---|---|---|
| 全仓（3 倍） | 1.30 | 1.10 | 币安全仓的默认 |
| 逐仓 3 倍 | 1.25 | 1.15 | |
| 逐仓 5 倍 | 1.20 | 1.10 | |
| 逐仓 10 倍 | 1.15 | 1.05 | 币安逐仓 10 倍的强平线 |
| 强平费 | — | 成交额的 2% | 入保险基金 |

为什么不是"亏到本金就强平"：借来的钱永远先于本金用于建仓、亏损永远先吃自己的保证金，若"一亏本金就强平"等于任何浮亏都强平。风险率 = 总资产 ÷ 负债，跌到接近 1 时资产只够还债，这才是必须强平的点；预警线给用户补保证金或减仓的机会。用户若想更保守，把预警线与强平线整体上调即可（后台可调）。

### 4.5 强平流程

1. 触发：风险率 ≤ 强平线（按 §2 估值，每秒重算一次或由价格事件驱动；连续两次命中才触发，避免单次毛刺）。
2. 冻结该杠杆账户（禁止下单、借币、划转），撤销其全部挂单。
3. 还款：同币种资产先直接抵债；剩余负债按"流动性优先"顺序用市价单对 HOUSE 卖出其它资产换回负债币种（全仓）或卖出该对的多头资产（逐仓）。
4. 收取强平费 2%（按平仓成交额）记入保险基金；剩余资产留在账户并解冻；资产不足以还清的部分由保险基金补足（`FundInsurance` 复用），并记穿仓事件。
5. 通知用户（站内信 + 邮件，复用 notification），强平记录可查（用户端与后台）。
6. HOUSE 侧：强平成交同样受 HOUSE 单资产上限与库存约束（`docs/runbook/market-maker.md`）；上限不足时强平单分批执行。

## 5. 交易与接口（草案，契约开发前给用户过目）

### 5.1 下单

- `POST /v1/orders` 增加 `account`：`SPOT`（默认）| `MARGIN_CROSS` | `MARGIN_ISOLATED`，以及 `side_effect`：`NONE` | `AUTO_BORROW`（可用不足时自动借入差额）| `AUTO_REPAY`（成交后自动用所得还债）。订单、撮合、成交事件不变，只多带账户类型；结算按账户类型记 `MARGIN_TRADE_SETTLE`。
- 杠杆下单前的资金检查：可用余额 + 可借额度 ≥ 冻结额；下单后风险率不得低于预警线（防止一下单就被预警）。

### 5.2 接口清单

| 方法与路径 | 说明 |
|---|---|
| `GET /v1/margin/assets` | 公开：各资产参数与当前利率、池余量 |
| `GET /v1/margin/pairs` | 公开：各交易对逐仓倍数与阈值 |
| `GET /v1/margin/accounts` | 登录：全仓账户 + 逐仓账户列表（资产、负债、风险率、净资产、强平价估算） |
| `POST /v1/margin/transfer` | 现货 ↔ 杠杆划转（`direction`、`account`、`asset`、`amount`） |
| `POST /v1/margin/borrow` / `POST /v1/margin/repay` | 借币 / 还币（`account`、`asset`、`amount`；还币可 `amount=ALL`） |
| `GET /v1/margin/loans` | 借款明细（本金、利息、模型、利率） |
| `GET /v1/margin/interest` | 计息流水 |
| `GET /v1/margin/liquidations` | 强平记录 |
| `GET /v1/margin/max-borrowable?account=&asset=` | 可借额度 |
| WebSocket 频道 `margin` | 账户风险率、负债、预警与强平事件推送 |

错误码按需求文档附录 C 风格新增：`MARGIN_LIMIT`（超可借额度）、`MARGIN_POOL_EMPTY`、`MARGIN_LEVEL_TOO_LOW`、`MARGIN_FROZEN`、`MARGIN_ASSET_NOT_BORROWABLE`。

### 5.3 事件（`api/proto`）

`margin.events`：`MarginBorrowed`、`MarginRepaid`、`MarginInterestAccrued`、`MarginLevelWarned`、`MarginLiquidationStarted/Completed`；ClickHouse 读模型 `margin_loans`、`margin_liquidations`、`margin_interest`。

## 6. 服务划分

- 新服务 **margin-service**（`cmd/margin-service`、`internal/margin/{domain,application,ports,adapters,transport}`，端口按 `server-deploy.md` 的表顺延）：账户、借还、计息、风险率、强平；通过 gRPC/HTTP 调账本（`Post`）、读行情估值、向 spot-trading-service 提交强平市价单（与 derivatives 的强平路径同构）。服务隔离规则（depguard）补一组。
- spot-trading-service：订单带 `account` 与 `side_effect`；下单前向 margin-service 询问可用（含自动借币）。
- ledger-service：新增账户类型、分录类型、不变量 7–9。
- notification：预警/强平模板（站内信、邮件）。
- 功能开关：`margin.enabled`（总开关，默认关）、`margin.liquidation`（强平执行，默认关，演练时打开）、`margin.auto_borrow`。

## 10. 验收要点

1. 借币后余额与负债同时增加，HOUSE `MARGIN_LENDING` 同步；不变量 7–9 每次对账通过。
2. 固定与浮动两种模型的计息可逐笔复算；整点计息在主备切换、Redpanda 重建后不丢不重（复用 inbox 去重）。
3. 风险率预警与强平按 §4.4 阈值触发；强平后负债为 0、强平费入保险基金、穿仓由保险基金补足；用户收到通知。
4. 全仓与逐仓隔离：逐仓账户的亏损不影响全仓；划转受风险率约束。
5. 杠杆单与现货单在撮合、行情、读模型里不可区分地正确结算；HOUSE 库存与上限约束仍成立。
6. 后台参数改动即时生效且有审计；利率/倍数/阈值改动需第二人。
7. 两站页面：风险率仪表、借还划转、通知；手机站 44 px 触控目标等既有检查清单项同样适用。

## 11. 风险与待决

- **ASTRA 作为可借资产**：薄市、价格由模拟市场控制，可被借出做空后砸盘；默认池上限低、折扣 0.70、逐仓 3 倍，并在后台可随时关闭可借；是否允许借出 ASTRA 待用户确认（建议先允许但上限低）。
- **估值来源**：跟随币安的交易对用币安 ticker，内部交易对（ASTRA、HOUSE 只报价的小币）用平台最新价；价格缺失时的保守处理见 §2。
