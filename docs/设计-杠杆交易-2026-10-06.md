## 1. 需求（用户确认）

1. 产品形态与币安杠杆交易一致：独立的杠杆账户，借币后在现货交易对上买卖，按小时计息，到期无强制还款，风险率过低预警、强平。
2. **全仓**（一个账户，多币种资产与负债互相覆盖）与**逐仓**（每个交易对一个账户，只含该对的两种资产）都做。
3. **倍数与币安一致**：全仓 3 倍（后台可放开到 5 倍）；逐仓按交易对 3 / 5 / 10 倍（后台按交易对配置，默认见 §4.2）。
4. **币种**：第一批可借与可作保证金的资产为 USDT、BTC、ETH，加 BNB、SOL、XRP、DOGE、ADA 等主流币（最终名单在 `deploy/instruments/test.json` 里按资产标记），以及平台币 ASTRA。
5. **利率模型两种都要**：固定小时利率（后台按资产设置）与浮动利率（按借贷池利用率），后台按资产选用哪一种。
6. 强平线与强平费：用户决定按行业做法——采用币安的风险率阈值与 2% 强平费（§4.4），后台可调。

与项目前提一致：学习项目、模拟资金、所有交易对手方是 HOUSE（ADR-0013/0015）。因此**借出方就是 HOUSE**，不需要真实的放贷用户与借贷池撮合；"借贷池"只是 HOUSE 为每种资产配置的可借上限。

## 2. 名词与核心模型

| 名词 | 定义 |
|---|---|
| 杠杆账户 | 与现货账户分开的账本账户：`MARGIN_CROSS`（全仓，一个）与 `MARGIN_ISOLATED:<symbol>`（逐仓，每交易对一个，首次划入时创建） |
| 资产 / 负债 | 账户内每种资产的余额（可为冻结与可用）与负债（借入本金 + 应计利息）；负债只能通过借币与计息增加、通过还币与强平减少 |
| 估值 | 一律折成 USDT：用平台该交易对的最新成交价（内部市场）或币安 ticker（跟随行情的交易对），与合约指数价同源；没有价格的资产不计入资产、按最保守方式计入负债 |
| 总资产 / 总负债 | 账户内全部资产估值之和 / 全部负债估值之和 |
| 风险率（margin level） | 总资产 ÷ 总负债；无负债时记为 ∞（显示 999） |
| 净资产（equity） | 总资产 − 总负债 |
| 可借额度 | min（净资产 × (倍数 − 1) − 已借，资产可借池余量，单用户上限，借后风险率不低于预警线的上限）按估值折算成该资产数量；页面给出的最大值总能借成功（2026-10-06 01:10 补"借后不低于预警线"一界，`limited_by` 记 `LEVEL`） |
| 倍数 | 全仓账户级（默认 3）；逐仓交易对级（默认见 §4.2） |
| 预警线 / 强平线 | 风险率阈值（§4.4）；低于预警线发通知，低于强平线由系统强平 |
| 强平 | 系统冻结账户、撤销全部挂单、以市价对 HOUSE 平掉仓位并归还负债，收取强平费，剩余归还用户；资产不足以还债的部分由保险基金承担 |

## 3. 账本（硬规则：余额只能经账本分录改变，ADR-0001）

### 3.1 账户与科目

- 用户：`MARGIN_CROSS`、`MARGIN_ISOLATED:<symbol>`（逐仓以 `scope` 列存交易对），每账户每资产三行：`balance`（资产，≥ 0）、`debt`（负债本金，**≤ 0 的负数行**）、`interest`（应计未还利息，≤ 0）。负债记成用户自己账户下的负数行，是因为账本每笔分录每种资产之和必须为 0（复式记账），"用户负债与 HOUSE 借出同增"记不平（2026-10-06 01:10 决定，E0 草案同此）。账本里"三行"即三个账户类型：`MARGIN_CROSS` / `MARGIN_CROSS_DEBT` / `MARGIN_CROSS_INTEREST` 与 `MARGIN_ISOLATED` / `MARGIN_ISOLATED_DEBT` / `MARGIN_ISOLATED_INTEREST`（E0 草案 §7.1–§7.2 的 CHECK 约束）；接口上只暴露 `MARGIN_CROSS` / `MARGIN_ISOLATED` + `symbol`（审查 CG 决定）。
- HOUSE：`MARGIN_INTEREST_INCOME`（利息收入，计息时确认；用户未还的部分就是其 `interest` 负数行，不另设应收账户）、强平费与穿仓补足直接记在合约的保险基金 `INSURANCE_FUND`（不设 `MARGIN_LIQ_FEE_INCOME` 中转，审查 CG 决定；保险基金的提取沿用既有双人审批）。HOUSE 的已借出额 `MARGIN_LENDING` 不单独记账，按资产 = −Σ 用户 `debt` 查询得出。
- 借贷池上限是配置（§4.1），不是账户余额：HOUSE 的可借出余量 = 上限 − `MARGIN_LENDING`。

### 3.2 分录类型（`ledger.entry_type` 新增）

| 类型 | 动作 | 不变量 |
|---|---|---|
| `MARGIN_TRANSFER_IN` / `MARGIN_TRANSFER_OUT` | 现货账户与杠杆账户之间划转；划出后风险率不得低于预警线，且不得划出被负债占用的资产 | 现货 + 杠杆总额守恒 |
| `MARGIN_BORROW` | 借入：用户 `balance` +A / 用户 `debt` −A（同一账户内平衡） | 借后可借额度 ≥ 0，池余量 ≥ 0，借后风险率 ≥ 预警线 |
| `MARGIN_INTEREST` | 每小时计息：每个账户 `interest` −i / HOUSE `MARGIN_INTEREST_INCOME` +Σi（按资产一笔汇总、每账户一行明细，E0 草案 §7.1）；不动 `balance` | 利息按 §4.3 公式逐笔可复算 |
| `MARGIN_REPAY` | 还币（先利息后本金）：用户 `balance` −(I+P) / `interest` +I / `debt` +P，全在用户自己的账户内平衡，HOUSE 不动（收入已在计息时确认） | 还款不超过负债 |
| `MARGIN_TRADE_SETTLE` | 杠杆账户上的成交结算：与 `HOUSE_TRADE_SETTLE` 同构，只是账户是杠杆账户 | 与现货结算同一套对账 |
| `MARGIN_LIQUIDATE` | 强平：系统市价成交后的还款、强平费、剩余归还、穿仓时保险基金补足 | 强平后账户负债为 0 |

### 3.3 不变量（`exchangectl ledger reconcile` 新增）

7. −Σ 用户 `debt`（按资产）= margin-service 借款表的未还本金，且 ≤ 该资产的借贷池上限。
8. 利息守恒：每笔 `MARGIN_INTEREST` 分录里 HOUSE 收入行 = −Σ 该分录的用户利息行（按资产）；HOUSE `MARGIN_INTEREST_INCOME` 余额 = 历史计息之和；每账户 −`interest` 行 = margin-service 借款表的未还利息。
9. 任一杠杆账户 `balance` ≥ 0、`debt` ≤ 0、`interest` ≤ 0；HOUSE 可借出余量（池上限 + Σ `debt`）≥ 0。

### 4.2 交易对参数（逐仓）

| 参数 | 默认 |

| 全仓倍数 | 账户级 3 倍（后台可改 5 倍，改动走双人审批） |

### 4.3 计息规则（与币安一致）

- 借入即计第一个小时的利息；之后每个整点按当时未还本金计一小时（`利息 = 本金 × 小时利率`），利息累入负债但不复利（利息本身不再计息）。
- 浮动模型按整点时刻的利用率取当小时利率，并记录在分录里，便于复算。
- 还款先抵利息、再抵本金；部分还款允许。
- 计息由 margin-service 的定时任务执行（每小时整点，带租约主备，失败重试；按资产一笔汇总分录 + 每账户明细）。

### 4.4 风险率阈值与强平费（用户 2026-10-05 决定按行业做法；2026-10-06 01:10 按"借满时风险率仍高于预警线"校正；后台可调，改动走双人审批）

| 账户 | 预警线 | 强平线 | 说明 |
|---|---|---|---|
| 全仓（3 倍） | 1.30 | 1.10 | 币安全仓的默认 |
| 逐仓 3 倍 | 1.25 | 1.15 | |
| 逐仓 5 倍 | 1.20 | 1.10 | |
| 逐仓 10 倍 | 1.10 | 1.05 | 借满 10 倍时初始风险率 10/9 ≈ 1.111，预警线必须低于它（原 1.15 会让 10 倍实际只能借到 7.7 倍） |
| 全仓 5 倍（后台开启时） | 1.20 | 1.10 | 借满时初始 1.25 |
| 强平费 | — | 成交额的 2% | 入保险基金 |

为什么不是"亏到本金就强平"：借来的钱永远先于本金用于建仓、亏损永远先吃自己的保证金，若"一亏本金就强平"等于任何浮亏都强平。风险率 = 总资产 ÷ 负债，跌到接近 1 时资产只够还债，这才是必须强平的点；预警线给用户补保证金或减仓的机会。用户若想更保守，把预警线与强平线整体上调即可（后台可调）。

### 4.5 强平流程

1. 触发：风险率 ≤ 强平线（按 §2 估值，每秒重算一次或由价格事件驱动；连续两次命中才触发，避免单次毛刺）。
2. 冻结该杠杆账户（禁止下单、借币、划转），撤销其全部挂单。
3. 还款：同币种资产先直接抵债；剩余负债按"流动性优先"顺序用市价单对 HOUSE 卖出其它资产换回负债币种（全仓）或卖出该对的多头资产（逐仓）。
4. 收取强平费 2%（按平仓成交额）记入保险基金；剩余资产留在账户并解冻；资产不足以还清的部分由保险基金补足（`FundInsurance` 复用），并记穿仓事件。
5. 通知用户（站内信 + 邮件，复用 notification），强平记录可查（用户端与后台）。
6. HOUSE 侧：强平成交同样受 HOUSE 单资产上限与库存约束（`docs/runbook/market-maker.md`）；上限不足时强平单分批执行。

## 10. 验收要点

1. 借币后余额与负债同时增加，HOUSE `MARGIN_LENDING` 同步；不变量 7–9 每次对账通过。
2. 固定与浮动两种模型的计息可逐笔复算；整点计息在主备切换、Redpanda 重建后不丢不重（复用 inbox 去重）。
3. 风险率预警与强平按 §4.4 阈值触发；强平后负债为 0、强平费入保险基金、穿仓由保险基金补足；用户收到通知。
4. 全仓与逐仓隔离：逐仓账户的亏损不影响全仓；划转受风险率约束。
5. 杠杆单与现货单在撮合、行情、读模型里不可区分地正确结算；HOUSE 库存与上限约束仍成立。
6. 后台参数改动即时生效且有审计；利率/倍数/阈值改动需第二人。
7. 两站页面：风险率仪表、借还划转、通知；手机站 44 px 触控目标等既有检查清单项同样适用。
