## 1. 需求（用户原话归纳）

- 现在整套系统以学习为目的：注册即送 10,000 USDT 等模拟资金，没问题。
- 将来要上线时，就按现在这套部署上去，**只在后台改改内容就能正式上线**：改配置、交易所名称、交易所 logo、平台币名称与 logo、文案、公告等。
- 注册赠送的金额必须可配置，上线时配成 0。
- 问：还有哪些应该做到"后台改就能上线"？

## 2. 原则

1. **后台能改的 = 产品与运营内容**：品牌、文案、公告、法律页、费率、上下架、限额、学习模式的开关。**只能在部署侧改的 = 密钥、域名、第三方账号、容器资源**（§3 F），写进上线手册，不进后台。
2. **上线不改代码、不重新构建前端**：品牌与文案在运行时从接口读取并注入，构建产物里只留默认值作为接口不可达时的回落。
3. **每项改动有审计**；涉及资金或用户风险的改动走现有的审批机制（§5）。

## 4. 设计

### 4.1 平台资料（branding）

- **存放**：instrument-service 新表 `platform_profile`（单行，版本号 + 更新人 + 更新时间），迁移 instrument 00008。放在 instrument-service 是为了复用资产资料已有的 logo 上传、清洗（方形 ≤ 256 px PNG/SVG）、1 分钟缓存与三端刷新机制（A1）。
- **字段**：`name`、`short_name`、`logo_light`、`logo_dark`、`favicon`、`apple_touch_icon`、`theme_color`、`brand_color`、`footer.copyright`、`footer.compliance`（备案/合规文案，可空）、`contact.email`、`contact.support_url`、`social[]{kind,url}`、`default_locale`、`test_mode{enabled, banner, text{"zh-CN","en"}}`（原 `learning_mode`，2026-10-04 18:45 更名；迁移 00009，`e4d36cc` 起旧名不再接受）、`registration{status: OPEN|CLOSED, closed_text{"zh-CN","en"}}`（多语言文案一律按语言键给，与资产资料的 description 一致，枚举大写；D1 契约 bfa754b）、`domain`（PC 站主机名，13:40 加入）、`updated_at`、`version`。
- **公开接口** `GET /v1/platform/profile`（网关白名单，公开，`Cache-Control: max-age=60`，`ETag` = version）；`GET /manifest.webmanifest` 由网关转到 instrument-service 动态生成（名称、短名、图标、主题色），m 站的 `index.html` 保持同一路径。
- **内部接口** `GET /internal/platform/profile` 供 notification-service（邮件主题与署名，缓存 10 分钟，失败回落到构建时常量）与 admin-service 读取。
- **站点注入**（pc/m/core）：`useBranding()` 在启动时读取并缓存；设置 `document.title`、`<link rel=icon|apple-touch-icon>`、`<meta theme-color>`、CSS 变量 `--brand-*`；所有 i18n 里的 `Astras` 改为 `{{brand}}` 插值；页脚、学习横幅、注册关闭提示从资料读；接口不可达时用构建时默认值（当前的 Astras 与图标），不白屏。
- **后台**：「平台设置」页（D2）：表单 + logo/favicon 上传（复用代币图标上传组件）+ 预览；保存即生效，审计 `admin.platform.updated`（带前后差异）；单人即可（§5）。
- **不做运行时注入的**：OG 标题/描述与 `index.html` 的 `<title>` 初值由部署 env 在构建时写入（爬虫不执行脚本），上线手册写明改法；首屏在脚本执行前短暂显示默认名称，可接受。
