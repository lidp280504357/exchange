## 2. 原则

1. **后台能改的 = 产品与运营内容**：品牌、文案、公告、法律页、费率、上下架、限额、学习模式的开关。**只能在部署侧改的 = 密钥、域名、第三方账号、容器资源**（§3 F），写进上线手册，不进后台。
2. **上线不改代码、不重新构建前端**：品牌与文案在运行时从接口读取并注入，构建产物里只留默认值作为接口不可达时的回落。
3. **每项改动有审计**；涉及资金或用户风险的改动走现有的审批机制（§5）。
4. **所有"学习模式"开关集中在后台一页看清**（§3 G「上线检查清单」）：每项当前值、上线应为的值、去修改的入口；全部达标才显示"可上线"。

## 4. 设计

### 4.1 平台资料（branding）

- **存放**：instrument-service 新表 `platform_profile`（单行，版本号 + 更新人 + 更新时间），迁移 instrument 00008。放在 instrument-service 是为了复用资产资料已有的 logo 上传、清洗（方形 ≤ 256 px PNG/SVG）、1 分钟缓存与三端刷新机制（A1）。
- **字段**：`name`、`short_name`、`logo_light`、`logo_dark`、`favicon`、`apple_touch_icon`、`theme_color`、`brand_color`、`footer.copyright`、`footer.compliance`（备案/合规文案，可空）、`contact.email`、`contact.support_url`、`social[]{kind,url}`、`default_locale`、`test_mode{enabled, banner, text{"zh-CN","en"}}`（原 `learning_mode`，2026-10-04 18:45 更名；迁移 00009，`e4d36cc` 起旧名不再接受）、`registration{status: OPEN|CLOSED, closed_text{"zh-CN","en"}}`（多语言文案一律按语言键给，与资产资料的 description 一致，枚举大写；D1 契约 bfa754b）、`domain`（PC 站主机名，13:40 加入）、`updated_at`、`version`。
- **公开接口** `GET /v1/platform/profile`（网关白名单，公开，`Cache-Control: max-age=60`，`ETag` = version）；`GET /manifest.webmanifest` 由网关转到 instrument-service 动态生成（名称、短名、图标、主题色），m 站的 `index.html` 保持同一路径。
- **内部接口** `GET /internal/platform/profile` 供 notification-service（邮件主题与署名，缓存 10 分钟，失败回落到构建时常量）与 admin-service 读取。
- **站点注入**（pc/m/core）：`useBranding()` 在启动时读取并缓存；设置 `document.title`、`<link rel=icon|apple-touch-icon>`、`<meta theme-color>`、CSS 变量 `--brand-*`；所有 i18n 里的 `Astras` 改为 `{{brand}}` 插值；页脚、学习横幅、注册关闭提示从资料读；接口不可达时用构建时默认值（当前的 Astras 与图标），不白屏。
- **后台**：「平台设置」页（D2）：表单 + logo/favicon 上传（复用代币图标上传组件）+ 预览；保存即生效，审计 `admin.platform.updated`（带前后差异）；单人即可（§5）。
- **不做运行时注入的**：OG 标题/描述与 `index.html` 的 `<title>` 初值由部署 env 在构建时写入（爬虫不执行脚本），上线手册写明改法；首屏在脚本执行前短暂显示默认名称，可接受。

### 4.2 注册赠送（可配置数额，上线为 0）

- ledger-service 新表 `ledger.settings`（键值，当前只有 `welcome_credits`：资产与数额列表，JSON 字符串金额），迁移 ledger 00007；启动时若表里没有值，用环境变量 `WELCOME_FUNDS` 作首值写入（兼容现状），之后以表为准，环境变量只做首值。
- `GrantWelcome`（`credits.go`）改读表（缓存 30 秒）；**数额列表为空或全为 0 即不发**，开关 `ledger.welcome_credit` 保留为总闸（两者都要满足才发）。
- 内部接口 `GET/PUT /internal/ledger/settings/welcome-credits`（admin-service 调用，带 actor 与 reason，审计 `ledger.settings.welcome_credits` 带前后值）。
- 后台「注册赠送」卡片（在「平台设置」页内）：显示当前列表与"上线应为 0"的提示；**降低或清零单人即可，提高或从 0 变非零走双人审批**（新审批类型 `WELCOME_CREDIT`，复用 SIM_MINT 的审批与限额护栏：单次上限 10,000 USDT 等值，超过硬拒绝）。
- 站点：注册页与首页的"注册即送 N"文案从 `GET /v1/platform/profile` 的 `welcome_credits`（只读镜像：instrument-service 每分钟从 ledger 的 `GET /internal/ledger/settings/welcome-credits` 读一次，内存保存，读失败保留上次的值——D1 的做法，后台少一步写、不会出现"ledger 已改而镜像写失败"的不一致；代价是站点最多约 2 分钟后才显示新数额，发放本身以 ledger 为准）读取；为 0 或空时不显示。

### 4.4 内容覆盖补齐

- 固定法律与信息页 slug：`terms`、`privacy`、`risk`、`fees`、`about`、`contact`，打包默认稿（中英）放进 `web/packages/core/content/legal/`；站点页脚链接到它们。
- 首页 hero：slug `home-hero`（frontmatter 只有 `title`、`subtitle`；按钮取正文里第一个 Markdown 链接，不另加字段），同一覆盖机制。
- 后台「内容」页：按 section/slug 列出每篇的来源（打包 / 接口覆盖）、最近更新、编辑与撤回（C4b 已有编辑，补"按固定 slug 的清单视图"与"未覆盖"标记）。
- **按模式分稿（2026-10-04 18:45 用户决定）**：每篇文章与打包稿带 `modes`（`TEST` / `FORMAL` / `BOTH`，默认 BOTH；打包稿用 frontmatter `modes:`），公开列表与详情按平台资料的 `test_mode` 过滤：测试模式只出 TEST/BOTH，正式模式只出 FORMAL/BOTH；切换模式自动换稿，不需要下架或覆盖；打包的「测试环境」公告标 TEST；编辑器可选模式；「固定页面」每个 slug 显示测试稿与正式稿两栏；「以默认稿发布」发布正式默认稿；检查清单"法律页"只认 FORMAL/BOTH 的已生效稿。
- **稿内按模式分段（2026-10-05 00:35 协调会话决定）**：BOTH 稿里只有个别段落因模式而异时，用 Markdown 条件块 `:::test` … `:::` 与 `:::formal` … `:::`（只认这两个标签、不嵌套、未闭合算到文末，其它 `:::xxx` 原样渲染）；过滤只实现在 core 的渲染器一处（内置稿、后台文章、后台编辑器预览共用，形如 `renderByMode(md, mode)`），服务端不剥块，接口文档注明正文可含模式块。内置稿改写：测试段落进 `:::test`，需要正式说法的写 `:::formal`；正式版充值/提现/费率指向充值页与费率表、不点名网络（托管切换已推迟）；两种模式都不写死赠送数额（注册赠送可配置、上线为 0）。演练在 FORMAL 模式下取 fees、deposit、faq 的渲染文本断言不含「测试环境」「模拟」「Sepolia」「10,000」，TEST 模式反向断言；core 单测覆盖块过滤。否决的替代方案：BOTH 稿不动、上线时人工发 FORMAL 覆盖稿（与用户"切模式自动换"的要求相悖）。「固定页面」的「以默认稿发布」把该 slug 已有的 BOTH 稿改为 FORMAL 专用并写入正式默认稿，测试模式下随即回落到打包的测试稿（每个 slug 每个模式只能有一篇生效，迁移 notify 00006 的部分唯一索引决定；页面提示已说明，2026-10-05 审查 BL 记录）。
