## 1. 需求（用户原话归纳）

1. 做一个自己的币，名字叫 ASTRA。
2. 做一个机器人服务，放很多机器人自动交易它、控制它的价格；价格可以设计成 BTC 与 ETH 的均价加随机值，有更好的方法更好。
3. 这个币也能做合约（永续）与杠杆。
4. 后台可以调整它的 logo 与名字；后台可以让它的价格突然升高或降低。

## 2. 决定与边界

## 3. 价格模型

记目标价 `P(t)`，机器人围绕它报价与成交，印出来的成交价围绕 `P(t)` 小幅波动。

```text
P(t) = P0 × M(t) × exp(X(t)) × E(t)

M(t)  市场因子：exp( β × ( w_btc × ln(BTC_t / BTC_0) + w_eth × ln(ETH_t / ETH_0) ) )
      BTC_t、ETH_t 取 market-data 内部参考价（币安）；BTC_0、ETH_0 是锚定时刻的价格
      默认 w_btc = w_eth = 0.5，β = 1.0（0 = 完全不跟随，>1 = 放大）
X(t)  自身波动：Ornstein–Uhlenbeck 过程 dX = −θ X dt + σ dW + μ dt
      默认 θ = 0.05/小时（均值回归），σ = 2%/天^0.5 换算到 tick 粒度，μ = 后台"趋势"（%/天，默认 0）
E(t)  事件因子：后台事件的乘积，见 §6.2；无事件时为 1
P0    锚定价，默认 1.0000 USDT；后台"重新锚定"把 P0 置为当前 P(t) 并重置 BTC_0、ETH_0
```

- 每 250 ms 推进一步；随机数用可配置种子，测试可复现。
- 守卫：无事件时每分钟最大变动 ±3%，价格下限 0.0001、上限 1,000,000，越界截断并告警。
- 为什么不用"BTC 与 ETH 均价"：两者价格差 30 倍，均价约等于 BTC 的一半，涨跌几乎只由 BTC 决定，而且 ASTRA 的价位会是四万多；用涨跌幅合成，ASTRA 可以是任意价位（默认 1 USDT 左右），走势与大盘相关但有自己的性格。

**印出来的成交价**：机器人做市在 `P(t)` 两侧挂单，噪声交易者随机吃单，所以成交价在 `P(t) ± 半个点差` 内跳动；事件发生时做市商先把报价移到新目标，吃单者沿途成交，K 线上形成自然的拉升或砸盘影线。

## 4. 机器人集群（market-sim 服务）

账户池：默认 24 个机器人用户（可配 8–64），注册为普通用户并打上 `bot` 标记，加入零手续费名单（沿用 `MARKET_MAKER_USER_IDS` 机制），现货账户持有 ASTRA 与 USDT，合约账户持有 USDT。

| 角色 | 数量（默认） | 行为 | 参数 |
|---|---|---|---|
| 做市商 Maker | 6 | 在 `P(t)` 两侧各挂 L 档，点差 s(t) 随 σ 调整，档位数量对数正态随机；`P(t)` 移动超过 k 个 tick 或每 1–3 s（带抖动）撤补 | L=8，s=0.2%，k=3 |
| 噪声交易者 Taker | 12 | 泊松到达（λ 单/分钟），随机方向（按趋势 μ 偏置）、随机数量，市价吃单 | λ 由日成交额目标反推 |
| 趋势交易者 | 4 | 按最近 N 分钟收益方向下单，制造自相关 | N=15，强度 0.3 |
| 事件执行者 | 2 | 事件期间沿目标路径分批吃单，确保印出来的价格跟上 `P(t)` | 批次间隔 1–2 s |

- 永续簿：做市商与噪声交易者在 ASTRA-USDT-PERP 上同样工作，报价中心用标记价；机器人之间多空自然对冲，净敞口由后台可见。
- 库存：每 10 分钟检查机器人余额，低于阈值时在机器人之间划转，整体不足时由运维脚本 `scripts/ops/astra.sh mint` 经 `ledger adjust` 增发到机器人池（审计），不直接改余额。
- 日成交额目标（USDT）：后台设置，服务据此调节 λ 与数量，并叠加日内季节性（亚洲/欧洲/美国时段权重）与事件期间的放大。
- 节流：全部机器人合计 ≤ 20 单/秒、≤ 10 撤单/秒（可配），对撮合与账本是轻负载。被拒绝的下单不消耗令牌，被拒的机器人按自身退避重试，做市商的撤补不得饿死吃单与趋势角色。
- **价格带不能把市场锁死（用户决定 2026-10-02）**。ASTRA-USDT 的价格带（±10%）锚点是最近一笔平台成交，而报价来自模型：目标价离锚点超过带宽时，所有档位都会被拒、簿空、无成交、锚点不再移动。三层避免：
  1. 做市阶梯始终钉在当前锚点的带内，目标价在带外时沿目标方向分步移动，每步留在带内且保证有成交（事件执行者/吃单配合），让锚点跟着走；后台"瞬时涨跌 ±x%"事件同样分批走完，不豁免价格带。
  2. 无参考交易对的锚点重锚：连续 5 分钟无成交时，锚点改为最近盘口中价或 market-sim 上报的目标价；锚点来源的优先级写进 trading/market-data 的 runbook。
  3. 看门狗：`sim.enabled` 开着却连续 3 分钟零成交或全部档位被 `ORDER_OUT_OF_BAND` 拒绝时自动重锚并告警 `MarketSimBandDeadlock`；`GET /internal/sim` 暴露锚点、目标价与带宽距离。
  验收：`scripts/e2e/astra.sh` 把目标价推到离最近成交 10% 以外（或暂停 5 分钟后恢复），无人工操作，3 分钟内恢复成交且两侧 ≥ 8 档。
- 状态持久化：集群参数、角色、每个机器人的会话令牌缓存、最近一次 `P(t)` 与随机状态存 PostgreSQL（`marketsim` schema）；重启后从最近状态继续，不出现断档。

## 5. 服务与数据

### 5.1 新服务 `market-sim`（`cmd/market-sim`，`internal/marketsim`）

```text
domain/        价格模型（纯函数 + 随机源接口，可复现）、事件状态机、机器人策略、节流与守卫
application/   250 ms 主循环：拉 BTC/ETH 参考价 → 推进 P(t) → 执行事件 → 各角色决策 → 发单/撤单；
               库存巡检；状态快照；指标
ports/         Prices（market-data 内部参考价）、Trading（现货/合约内部下单接口）、Accounts（机器人账户与余额）、
               Store（参数、事件、机器人、状态）、Clock、Rand
adapters/      http（trading-service、derivatives-service 内部 API，复用退役前 market-maker 的客户端）、postgres、
               flags
transport/     管理 gRPC/HTTP（给 admin-service）：参数读写、事件、集群状态、实时目标价流（SSE）
```

- 单实例，`pg.AcquireLease("market-sim")` 主备。
- 指标：目标价、印出价、点差、每分钟成交额、每角色下单/撤单数、机器人库存、守卫触发次数。
- 事件主题 `market.sim.events`（事件开始/结束、守卫触发、库存增发）进 ClickHouse 供后台图表。

### 6.2 事件类型

| 类型 | 参数 | 行为 |
|---|---|---|
| `JUMP` | 幅度 ±%（≤ 30%），持续 0–600 s | 0 s 为瞬时：`E(t)` 立即乘以 (1+幅度)，事件执行者在 2–5 s 内把印出价推到位；>0 s 为线性或指数路径 |
| `TARGET` | 目标价，时长 | 从当前价按指数路径到达目标价后保持 |
| `TREND` | %/天，可带结束时间 | 修改 μ |
| `VOLATILITY` | σ 倍数，时长 | 临时放大/缩小波动 |
| `PAUSE` | 时长 | 冻结 `P(t)`，做市商维持报价，噪声交易者停止 |
| `HALT` | | 撤销全部机器人挂单，交易对置 `HALT`；恢复时重新报价 |
| `REANCHOR` | | P0 := 当前价，重置 BTC_0、ETH_0 |

守卫：单次 JUMP ≤ ±30%、每小时累计 ≤ ±50%，超过需双人审批（复用提现双人审批机制）；事件期间后台显示"事件进行中"横幅。**2026-10-02 澄清（A3 审查）**：
- 预算按事件的 `starts_at` 所在小时窗口累计（不是创建时间），`starts_at` 不得晚于现在 + 24 h；TREND（按 24 h 累计漂移折算）与 VOLATILITY（按倍数折算）同样计入预算；双人审批后的 JUMP 仍有硬上限 ±100%。
- 参数变更走同一套守卫：`p0`、`max_minute_move`、`floor`、`ceiling`、`daily_volume` 的改动按其对价格/成交的影响计入预算并可能需要第二人；`max_minute_move` 硬上限 5%/分。
- 审批人身份来自调用方凭据（admin-service 用内部共享密钥签名或 mTLS 调用 market-sim），不是请求体里的名字；审批记录持久化为对象并进审计。
- REANCHOR 必须写回持久化的设置并记为事件；重启或参数更新后目标价不得走回旧 P0。
- 任何事件都在价格带内分步执行（见 §4）；事件不豁免价格带。

### 6.3 用户影响提示

价格事件会触发持有 ASTRA 永续仓位的用户强平。确认框显示：当前多/空仓位数、按目标价估算会被强平的仓位数与保险基金预计承担额。学习项目允许，但必须看见。

## 8. 验收标准汇总

1. 后台能改 ASTRA 的显示名与图标，三端 1 分钟内刷新，旧图标不被缓存污染。
2. ASTRA-USDT 全天有连续 K 线、盘口（≥ 8 档/侧）、成交流水；用户市价单在 0.3% 点差内成交；限价单可挂可成交。
3. 价格跟随：BTC 与 ETH 同向变动 1% 时，ASTRA 目标价变动约 β × 1%；无事件时每分钟变动不超过 3%。
4. 后台事件：瞬时 ±x% 在 5 s 内到位；目标价事件按路径到达；守卫与审批生效；全部操作可在审计里查到操作人、参数、前后价格。
5. 永续：ASTRA-USDT-PERP 可开多开空、设置止盈止损、资金费结算；指数价来自平台现货；事件触发的强平走保险基金与 ADL。
6. 机器人库存自动巡检；集群重启不中断行情超过 5 s；全部机器人零手续费；机器人订单与成交在后台可按 `bot` 标记过滤。
7. 用户不能充提 ASTRA；资产页估值用平台价。

## 9. 风险

| 风险 | 应对 |
|---|---|
| 人为控盘在真实市场属于操纵，学习项目可做 | ADR-0016 记录；上线前门禁 |
| 事件导致用户大面积强平、保险基金穿仓 | 守卫、双人审批、确认框显示影响；ASTRA 永续风险阶梯名义上限缩小 10 倍 |
| 机器人订单风暴 | 合计节流 ≤ 20 单/秒；做市撤补带抖动 |
| 价格守卫与事件冲突 | 事件显式豁免守卫，事件结束后守卫恢复 |
| 价格带死锁：目标价离最近成交 >10%，全部档位被拒、簿空、锚点不动 | §4 的三层：阶梯钉在带内分步走价、无参考交易对 5 分钟无成交重锚、看门狗自动重锚 + 告警；e2e 用例验证无人工干预 3 分钟内恢复 |
| 机器人账户余额被当作用户负债 | 账本对账把 `bot` 标记账户归入平台侧；后台持有分布区分 |
| market-sim 宕机 | 主备租约；宕机时做市商挂单仍在簿上，噪声停止；超过 60 s 无心跳则交易对自动 `HALT` 并告警 |
