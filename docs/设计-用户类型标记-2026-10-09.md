## 1. 取值

| # | 事项 | 取值 |
|---|---|---|
| 1 | 类型 | `kind`：`HUMAN` 真人（默认）、`BOT` 机器人（模拟市场的账户）、`TEST` 测试账号（端到端脚本注册的）、`SYSTEM` 系统账户（HOUSE 等） |
| 2 | 存放 | user-service 的 `users.kind`（迁移 users 00004，`NOT NULL DEFAULT 'HUMAN'`，索引），改动审计（from/to/actor/reason） |
| 3 | 谁打标 | 只有运维与脚本：`exchangectl users kind`、内部 `PUT /internal/users/{id}/kind`（compose 网络内）；`astra.sh seed` 把机器人标 `BOT`、HOUSE 标 `SYSTEM`（新增 `astra.sh mark`，幂等，可补标）；端到端脚本注册用户后标 `TEST`（失败只警告）；后台不提供改类型的操作 |
| 4 | 存量 | 测试服现有账户一次性补标：`astra.sh mark` 补机器人与 HOUSE；老的端到端账户按邮箱 `e2e-%@example.com` 标 `TEST`（命令或 SQL 写进 accounts.md） |
| 5 | 后台 | 用户列表加「类型」列（枚举标签）与筛选（可多值），**默认只看真人**；详情页顶部标签；概览的用户数默认只算真人、小字给机器人/测试数；admin.yaml 的用户列表加 `kind` 筛选与字段 |
| 6 | 对外 | 公开接口不暴露 `kind`；两站不变 |
| 7 | 机器人是正式功能（用户 2026-10-09 22:1x 叮嘱） | 平台币的机器人上线后照常买卖 ASTRA，控价时必须有机器人交易；`kind` 只用于后台显示与统计，交易、手续费、风控、通知与 market-sim 的调度一律不读 `kind`；后台的"默认只看真人"只作用于用户列表与概览的用户数，模拟市场与价格事件页面照旧显示全部机器人；上线检查清单不含"关闭机器人"，上线手册里机器人的 seed 与打标是正式步骤 |
| 8 | 后台所有用户维度的列表与报表（用户 2026-10-10 00:0x） | 凡是按用户维度的列表与报表都加「类型」筛选，**默认只看真人**：用户、订单（现货/杠杆/合约）、成交、仓位、强平记录（合约与杠杆）、资金费、ADL、充提与划转、资金流水、借还款与利息、风险预警、概览与报表的用户数/交易量/持仓量（默认只算真人，小字给机器人/测试数）。HOUSE、模拟市场、价格事件、审计页不受影响。实现：user-service `GET /internal/users/ids?kind=…` 给出非真人 ID 集（admin-service 缓存 60 秒）；走 ClickHouse 读模型的列表用 `has()`/`NOT has()`；走各服务内部接口的实时列表加 `exclude_user_ids` / `user_ids`（≤ 1,000） |
