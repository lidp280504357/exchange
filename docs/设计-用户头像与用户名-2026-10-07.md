## 1. 范围与取值

| # | 事项 | 取值 |
|---|---|---|
| 1 | 用户名 | 新字段 `username`：注册时生成 `user_` + 8 位小写字母数字（唯一，重试到不冲突）；用户可改：3–20 字符，字母、数字、下划线，不能以下划线开头，唯一（不分大小写，`citext`），保留词（admin、support、astras、house 等）拒绝；7 天只能改一次；改名审计到用户的安全事件（不发邮件）。登录仍用邮箱/手机，用户名只作展示与称呼 |
| 2 | 头像上传 | `POST /v1/account/avatar`（multipart，`image/png`、`image/jpeg`、`image/webp`，≤ 5 MB，边长 ≥ 64）；服务端解码（只认真实图片格式）、居中裁成正方形、缩放为 256×256 与 64×64 两张 WebP、去 EXIF，写入 `infra/uploads/avatars/<user_id>/<随机>.webp`，返回 URL；旧文件在新头像写入后删除；`DELETE /v1/account/avatar` 回到默认头像 |
| 3 | 存放与分发 | 服务器磁盘 `infra/uploads/avatars/`（user-service 挂载读写，nginx 只读），nginx `location /uploads/avatars/ { expires 30d; add_header Cache-Control "public, max-age=2592000, immutable"; types { image/webp webp; } }`，三站共用；文件名随机，所以更新头像即换 URL，不用清缓存。备份不含头像（可重新上传） |
| 4 | 默认头像 | 两站内置 12 个 SVG 头像（颜色 + 几何图形，无文字），按用户 ID 的哈希选一个；`avatar_url` 为空即用默认；后台看到的也是同一规则 |
| 5 | 显示位置 | PC：顶栏用户菜单的触发器与菜单头部、账户页左栏、个人资料页；手机：「我的」页头、设置页、个人资料页；通知中心与公告不显示头像。头像组件 `Avatar`（`packages/ui`，新文件）统一处理默认与加载失败回退 |
| 6 | 后台 | 用户列表与用户抽屉显示用户名与头像（只读）；后台可「重置头像」「重置用户名」（违规处理：重置为默认头像 / 随机用户名，单人、审计 `admin.users.avatar_reset` / `username_reset`，用户收到站内信） |
| 7 | 接口形状 | `GET /v1/account/profile` 增加 `username`、`avatar_url`（256）、`avatar_thumb_url`（64）、`username_changed_at`；`PUT /v1/account/username {username}`（错误码 `USER_USERNAME_TAKEN`、`USER_USERNAME_INVALID`、`USER_USERNAME_COOLDOWN`）；`POST/DELETE /v1/account/avatar`（`USER_AVATAR_INVALID`、`USER_AVATAR_TOO_LARGE`）；网关加 `/v1/account/avatar` 的 multipart 透传与 8 MB 限制；WebSocket 不推 |

不在范围：裁剪器（先用居中裁剪，后续可加）、GIF 动图、昵称与用户名分开、P2P 场景。

## 2. 数据（user-service，迁移 user 000xx）

`users` 加 `username citext UNIQUE NOT NULL`（回填：现有用户按规则生成）、`username_changed_at`、`avatar jsonb`（`{path, thumb_path, uploaded_at, size, sha256}`，空即默认）。注册路径（`internal/user`、`internal/auth` 的注册流程）在创建用户时生成用户名。

## 4. 风险

- 上传的图片只按真实格式解码，拒绝 SVG 与非图片；服务端不保存原图；路径不接受用户输入。
- 用户名唯一性回填：现有用户（测试账号）按规则生成，不会与真实用户冲突（测试服无真实用户）。
- Cloudflare 对 `/uploads/avatars/` 的缓存按 30 天不可变，更换头像即换文件名，不会显示旧图。
