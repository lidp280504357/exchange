## 1. 范围与理解

### 1.1 用户要求（原话）

做个下载页面，可以下载安卓和 iOS 的 App，下载链接后台配置。另外也可以直接上传，上传安卓 APK 和苹果的描述文件（上传后生成 URL，自动配置上去，然后上传的 App 也可以删除）。

### 1.2 理解与取值

| # | 事项 | 取值 | 说明 |
|---|---|---|---|
| 1 | 两种来源 | 每个平台（Android、iOS）各自二选一：**外部链接**（应用商店、TestFlight、第三方分发页）或 **上传的文件**；也可关闭 | 后台切换，页面按当前配置显示 |
| 2 | Android | 上传 `.apk`（校验 zip 结构含 `AndroidManifest.xml`，解析包名与版本），生成 `https://<站点>/downloads/android/<文件>` | 下载即安装，页面附"允许安装未知来源"说明 |
| 3 | iOS「描述文件」（**待确认**） | 默认理解为 **OTA 安装清单**：后台上传企业签名或 Ad Hoc 的 `.ipa`，服务端解析 `Info.plist`（bundle id、版本、名称）自动生成 `manifest.plist`，页面按钮为 `itms-services://?action=download-manifest&url=https://<站点>/downloads/ios/manifest.plist`；**另可选**上传 `.mobileconfig`（配置描述文件，如企业信任或 Web Clip），单独一个下载项 | 若用户指的只是 `.mobileconfig`，同一上传机制已覆盖；App Store 上架的 App 用外部链接 |
| 4 | 存储与分发 | 文件放服务器磁盘 `infra/downloads/{android,ios}/`，nginx 直接提供 `/downloads/*`（三站同一目录），不经接口、不进数据库；单文件上限 500 MB；旧版本在上传新版本后保留到手动删除 | 测试服磁盘余 18 GB |
| 5 | 上传方式 | 后台分片上传（10 MB 一片，断点续传，服务端合并后校验类型与 SHA-256） | Cloudflare 代理的单请求上限 100 MB，APK 常超过 |
| 6 | 配置落在哪 | 平台资料的延伸：instrument-service 新表 `platform_apps`，公开 `GET /v1/platform/apps`，后台经 admin-service 写（与平台资料同一路径与权限） | "一套部署、后台改配置即上线"的口径 |
| 7 | 删除 | 后台可删除已上传的文件（含自动生成的 manifest），删除后该平台自动回到"未提供"或外部链接；审计 | 单人操作（不涉及资金），有审计 |
| 8 | 页面 | 两站 `/download`；PC 显示两个平台的卡片与二维码，手机按 UA 突出本机平台；页脚与手机「我的」加入口；三语 | 未配置任何平台时页面显示"暂未提供"，入口隐藏 |

### 1.3 不在范围

应用内更新检查接口（可后续加 `GET /v1/platform/apps` 的版本比较）；苹果 App Store Connect / Google Play 的自动发布；安装包的病毒扫描。

## 2. 数据与接口

### 2.1 数据（instrument-service，迁移 instrument 000xx）

`platform_apps`：`platform`（`ANDROID` | `IOS`，主键）、`mode`（`OFF` | `LINK` | `FILE`）、`link_url`、`file`（jsonb：`name`、`size`、`sha256`、`stored_as`、`uploaded_at`、`uploaded_by`、`package`/`bundle_id`、`version`、`build`、`min_os`）、`manifest_url`（iOS，自动生成）、`extra_file`（iOS 可选 `.mobileconfig`，同 `file` 结构）、`notes`（多语言 `{"zh-CN","en","zh-TW"}`）、`enabled`、`version`（乐观锁）、`updated_by`、`updated_at`。

### 2.2 公开接口（`api/openapi/platform.yaml`）

- `GET /v1/platform/apps` → `{ android: AppDownload | null, ios: AppDownload | null }`，只返回 `enabled` 且配置完整的平台；`AppDownload { mode, url, version, build, size, sha256, notes, updated_at, ios_install: "APP_STORE" | "OTA", mobileconfig_url? }`；缓存 60 秒（与 profile 相同）。

### 2.3 后台接口（`api/admin/admin.yaml`，admin-service → instrument-service 内部接口）

- `GET /admin/v1/platform/apps`、`PUT /admin/v1/platform/apps/{platform}`（mode、link_url、notes、enabled、expected_version）；
- 分片上传：`POST /admin/v1/platform/apps/{platform}/uploads`（文件名、大小、sha256 → `upload_id`）、`PUT /admin/v1/platform/apps/{platform}/uploads/{upload_id}/parts/{n}`（10 MB 一片，nginx 该路由 `client_max_body_size 16m`）、`POST …/uploads/{upload_id}/complete`（合并、校验 zip 结构与 sha256、解析版本、生成 iOS manifest、写入 `platform_apps`、返回 URL）；未完成的上传 24 小时清理；
- `DELETE /admin/v1/platform/apps/{platform}/file`（删文件与 manifest，`mode` 回到 `OFF` 或保留 `LINK`）；`kind=mobileconfig` 的上传与删除同上；
- 权限沿用平台资料（`platform.write`），单人，审计 `admin.platform.app_updated` / `app_file_uploaded` / `app_file_deleted`（详情含平台、文件名、大小、sha256）。

### 2.4 文件存放与 nginx

- admin-service 挂载 `infra/downloads`（读写），nginx 挂载同一目录（只读）：`location /downloads/ { alias …; types { application/vnd.android.package-archive apk; application/octet-stream ipa; application/xml plist; application/x-apple-aspen-config mobileconfig; } add_header Content-Disposition "attachment" (apk/ipa); add_header X-Content-Type-Options nosniff; expires 1h（manifest 不缓存）; }`；三个 server 块共用。
- 文件名随机（UUID + 原始扩展名），原名只在配置里记录；路径不接受用户输入（防穿越）；`manifest.plist` 的 `url` 指向本站 HTTPS 地址（Cloudflare 已有证书；OTA 安装要求 HTTPS）。
- 服务器备份不含安装包（可重新上传）；`server-deploy.md` 加目录与权限说明。

## 3. 后台页面（H2）

「平台设置」下新页「App 下载」：两张卡片（Android、iOS），各有：模式（关闭 / 外部链接 / 上传文件）、链接输入、上传区（分片进度、校验结果：包名/bundle id、版本、大小、SHA-256）、版本说明（三语页签）、启用开关、「删除文件」（确认框，写明删除后页面的状态）；iOS 卡片另有「配置描述文件（可选）」上传与删除；顶部提示 OTA 安装要求企业或 Ad Hoc 签名。冒烟：打开页面、切换模式、上传一个小的伪造 apk（测试用最小 zip）并删除。

## 4. 站点页面（H3）

- 两站 `/download`：标题、两张平台卡片（图标、版本、更新时间、大小与 SHA-256 可复制、「下载 / 安装」按钮、安装说明折叠：Android 允许未知来源，iOS OTA 的"设置 → 通用 → VPN 与设备管理 → 信任"）；PC 卡片带二维码（指向本页或直接指向文件；OTA 指向 `itms-services` 链接的二维码要用页面地址）；手机按 UA 把本机平台放前面并直接给安装按钮；未配置的平台不显示；两个都未配置时整页"暂未提供"。
- 入口（02:5x 决定）：PC 顶栏右侧「下载」（悬停弹出 Android/iOS 二维码与「打开下载页」链接，与币安顶栏一致）与页脚「关于」列的「下载 App」；手机「我的」列表项与设置页的「下载 App」；未配置任何平台时入口隐藏；三语文案走现有生成流程。
- 冒烟：两站打开 `/download`（无配置与有外部链接两种状态）；perf 不进首屏。

## 6. 风险

- OTA 安装只对企业签名或 Ad Hoc 的包有效，App Store 上架的用链接；描述文件若指 `.mobileconfig`，按 §1.2 #3 的可选项处理。
- Cloudflare 的单请求上限用分片上传规避；下载走 Cloudflare 代理没有响应大小限制，但大文件不缓存（源站直出，带宽受测试服限制）。
- 文件类型校验只看结构与扩展名，不做病毒扫描（学习项目）。

## 7. H0 契约（后台会话，04:20）

接口以 [platform.yaml](../api/openapi/platform.yaml) 的 `GET /v1/platform/apps` 与 [admin.yaml](../api/admin/admin.yaml) 的 `/admin/v1/platform/apps*` 为准，表结构见 `migrations/instrument/00013_platform_apps.sql`。下面是契约里与 §2 不同、或 OpenAPI 写不下的取值（不答即按此做 H1）：

| # | 事项 | 取值 | 理由 |
|---|---|---|---|
| 1 | 删除的对象 | `DELETE /admin/v1/platform/apps/{platform}/files/{file_id}`（按文件，不是 §2.3 的 `…/file`）；列表 `files` 列出该平台服务器上保留的全部文件（最新在前），`current` 与 `mobileconfig` 指向其中正在用的 | §1.2 #4"旧版本在上传新版本后保留到手动删除"：保留多份就要能指定删哪一份；删正在用的安装包时平台回到外部链接（有）或关闭（§1.2 #7） |
| 2 | 上传完成即生效 | `…/complete` 把新安装包设为当前、模式改为 `FILE`（§1.2"上传后生成 URL 自动配置上去"）；`enabled` 不动（关着的平台上传后仍不显示，后台再打开）；`.mobileconfig` 替换并删除旧的那份 | 上传与"是否对外"分开，后台可以先传好再开 |
| 3 | 地址 | 接口里的 `url`、`install_url`、`mobileconfig_url` 都是绝对地址 `https://<平台资料的 domain>/downloads/...`（domain 为空时用后台所在站点，`admin.<站点>` → `<站点>`）；`manifest.plist` 在上传时写死这个地址，改域名后要重新上传 .ipa | OTA 安装要求清单与安装包都是 HTTPS 绝对地址；nginx 三个站点共用 `/downloads/` |
| 4 | 文件名与目录 | 存为 `<file_id>.<扩展名>`（.ipa 的清单 `<file_id>.plist`），目录 `infra/downloads/{android,ios}/`；分片在单独的 `infra/app-uploads/<upload_id>/`（nginx 不挂载），24 小时未完成即删 | 路径不来自用户输入；上传中的分片不对外 |
| 5 | 大小 | 单文件 ≤ 500 MiB（524,288,000 字节；`.mobileconfig` ≤ 1 MiB），分片 10 MiB（最后一片为余数），nginx 只对 `…/parts/{n}` 放宽到 16 MB | Cloudflare 单请求 100 MB；其余后台接口保持现有限制 |
| 6 | 校验（`PLATFORM_APP_FILE_INVALID`，details `reason`） | 大小与 SHA-256 等于开始时声明的；.apk 是 zip 且有 `AndroidManifest.xml`（二进制 XML，读包名、versionName、versionCode、minSdkVersion）；.ipa 是 zip 且有 `Payload/<名>.app/Info.plist`（二进制或 XML plist，读 CFBundleIdentifier、CFBundleShortVersionString、CFBundleVersion、MinimumOSVersion）；.mobileconfig 为 plist（或其 CMS 签名封装）且 `PayloadType` 为 `Configuration` | §1.2 #2、#3；不做病毒扫描（§1.3） |
| 7 | 公开接口 | `null` 表示该平台不显示（关闭、未启用、链接为空或文件缺失）；ETag 为两行 `version` 之和（每次改动只给一行加一，严格递增；审查 FF ① 更正"较大者"），缓存 60 秒；`ios_install` 链接模式为 `APP_STORE`（含 TestFlight 与其他页面）、上传模式为 `OTA`，安卓为 `null` | 与平台资料同一缓存口径；站点只看 `null` 决定入口显隐（§4） |
| 8 | 版本与审计 | `version` 在设置、上传、删除时都加一，`PUT` 带 `expected_version`（不符 409 `INSTRUMENT_PLATFORM_CHANGED`）；instrument-service 的 `config_history` 记 `PLATFORM_APP` 的前后（迁移同时放开实体约束）；后台审计 `admin.platform.app_updated`、`app_file_uploaded`、`app_file_deleted`（详情：平台、种类、原名、大小、SHA-256、包里读出的版本，不含文件内容） | 与平台资料一致（§2.3） |
| 9 | 内部接口（不进 OpenAPI，H1 实现） | instrument-service `GET /internal/platform/apps`、`PUT /internal/platform/apps/{platform}`（设置）、`POST /internal/platform/apps/{platform}/files`（记一份已存的文件并设为当前）、`DELETE /internal/platform/apps/{platform}/files/{file_id}`；网关 `routes.go` 加公开的 `GET /v1/platform/apps` | 与 `/internal/platform/profile` 同一套 |
| 10 | 部署（H1 随代码一起改，H0 不动线上） | compose：admin-service 挂 `./downloads:/srv/downloads` 与 `./app-uploads:/srv/app-uploads`（读写），nginx 挂 `./downloads:/usr/share/nginx/downloads:ro`；`server-update.sh` 建目录并交给容器用户（uid 10001）；nginx 三个 server 块 `location /downloads/`（`.apk` 带 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、安装包缓存 1 小时、`.plist` 不缓存、拒绝点文件），后台 server 块对 `…/parts/` 路由 `client_max_body_size 16m` | 挂载与目录在 H0 落地时没有代码写入，又要重建 nginx 容器；H1 一次带上并在部署中验证 |
| 11 | 字段名（相对 §2.1） | §2.1 的 `file`、`manifest_url`、`extra_file` 在契约与迁移里为 `current`（当前安装包）、`mobileconfig`（iOS 可选配置描述文件）与 `files`（服务器上保留的全部文件，最新在前）；清单地址在文件对象的 `manifest_url`（.ipa）里 | 保留多份文件（#1）后，单个 `file` 不够用 |
| 12 | 上传状态（审查 FF ⑤） | H1 在 admin 库加迁移 `app_uploads`（upload_id、platform、kind、name、size、sha256、已收分片、expires_at、started_by），分片仍在磁盘；域名改动时 H1 可重新生成各 .ipa 的 manifest（可选，FF ③ 的补充） | admin-service 重启后能续传、能按期清理 |
